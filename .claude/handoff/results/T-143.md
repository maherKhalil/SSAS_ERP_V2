## ⚠ Attendance is the finding: 0 of 17

**Not one Attendance command handler appears in any Integration test.** Attendance reaches the Integration
suite in only three ways, none of which is a handler:

```
AttendanceSchemaSqlServerTests     column types and constraints, no application code
```

**So every attendance write — recording, adjusting, approving leave, closing a period, defining a
calendar — is tested only against stubs.** `AddHoliday`, `AdjustAttendance`, `ApproveLeaveRequest`,
`CancelLeaveRequest`, `CloseAttendancePeriod`, `CreateAttendancePeriod`, `CreateLeaveType`,

## And the stubbing is product-wide, not GL's peculiarity

**Every module's API tests stub their repositories.** That is a reasonable design for route tests — but it

does.

# ⚠ HOW I MEASURED, AND THE FIRST TWO METHODS WERE BOTH WRONG

**This took three passes and the first two disagreed by a factor of twenty on HR alone.**

```
1. raw name match                 HR 43 "covered"   -> counts names in COMMENTS (DEC-L-074)
2. `new X(` construction match    HR  2 "covered"   -> misses target-typed `new(`, which HR uses
3. name match, COMMENTS STRIPPED  HR 43            -> agrees with 1, for a defensible reason
```

**Pass 1 was right by accident and pass 2 wrong by precision.** `CreateEmployeeCommandHandler` appears twice
in prose in `EmployeeBoundarySqlServerTests` **and** once as real code at line 4514 — `public
CreateEmployeeCommandHandler Create() => new(` — **a target-typed `new` the construction regex could not
see.** Stripping comments and then matching names is the only pass that answers the question asked.

**The floor, stated: "named in code" is not "executed".** A handler referenced in a helper that no test
calls would count as covered here. **So 73 is the optimistic side and 75 is a floor on the gap** — the true
number of never-executed handlers is 75 or higher, never lower.
