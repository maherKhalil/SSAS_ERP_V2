# T-068 — Employment type: establish the blast radius, build nothing

**Measurement task. No `src/`, no `tests/`, no schema. Non-gated.**

## Why this exists

The owner surfaced it 2026-08-27 while answering a self-service question: *"an external accountant
may be not full time but he will get paid, so he should have an employee record with type part time
or freelance."*

**Verified: the concept does not exist.**

```
Employee      no employment-type field
Position      no employment-type field
src/          no EmploymentType / EmployeeType / ContractType / WorkType enum anywhere
FP-006 spec   part-time / full-time / freelance / contractor never mentioned
```

**The ruling presumes a concept the product does not have.** It is not blocking FP-015 — nothing
there reads it — but it is a real gap, and the reason it needs measuring before specifying is that
**it is cross-cutting rather than an HR field.**

## What to establish — and do not stop at the obvious one

**1. Payroll.** `OD-PAY-0015` records proration as **calendar days, unchanged, "the lever is recorded
as untaken."** Part-time employment is exactly that lever. **Find every place proration is computed
and report what a non-full-time employee would do there today.** Not what it should do — what it
does.

**2. Attendance.** The working calendar assumes one shape. `WorkingCalendar`, expected hours, leave
accrual. **Report which of them would produce a wrong answer rather than an error** — a wrong answer
is the expensive case and the one that will not announce itself.

**3. Leave entitlement.** Ordinarily pro-rated by type. Establish whether it is computed anywhere
today and against what.

**4. Anywhere else.** `grep` is not enough here — a concept absent from the model is absent from the
grep. **Look for the places that would need to ask and currently cannot**, which is a different
search from looking for a name that does not exist.

## What NOT to do

- **Do not add a field, an enum, a migration, or a configuration.** This is FP-006's to specify and
  the owner's to rule.
- **Do not propose a design.** The question is *what does this touch*, not *how should it work*.
- **Do not assume the answer is uniform.** Payroll may need a ratio, attendance a schedule, leave a
  policy — three different shapes wearing one name is exactly what makes a cross-cutting concept
  expensive, and reporting them as one number would hide it.

## Done when

- Each of the four areas is reported with **file and line**, not a summary.
- For each site: **what happens today for an employee who is not full-time** — correct, wrong-answer,
  or error. **Wrong-answer sites listed first**, because they are the ones nobody would find.
- Anything you cannot establish is **named as unestablished** rather than omitted.
- No file under `src/`, `tests/`, or `docs/` is modified. **A result file only.**

**No check-back needed. Report when done.**
