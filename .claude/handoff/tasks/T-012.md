# T-012 — `Authentication.md` takes the supersession-disclaimer shape

- **Branch:** `agent/T-012-authentication-disclaimer` — branch from `main`
- **Module:** Docs / platform functional
- **Issued:** 2026-08-25
- **Depends on:** T-018 (merged, PR #66)

## Goal

`docs/02-Functional/Platform/Authentication.md` carries `status: Draft` while supplying rules that
approved packages rely on. It has come up three times: `REQ-SUB-0018` cited it as **non-authoritative**
and carried its expired-subscription login rule as a *candidate*; `OD-SUB-0009` then ruled that rule
**binding**; and `trace-check` reports `BR-PLT-0100`/`0101` as UNTRACED with this file among their
citations.

So a `Draft` document is the origin of a ruled requirement. `Tenant-Management.md` already solved this
exact problem for itself — it names which approved package supersedes which of its sections and
declares the remainder non-authoritative. This gives `Authentication.md` the same treatment.

**This is not a rewrite and not a promotion to `Approved`.** It makes the document say honestly which
parts are superseded, by what, and which remain deferred.

## Acceptance criteria

- [ ] `Authentication.md` gains a **Lifecycle authority** block in `Tenant-Management.md`'s shape,
      naming the approved packages that supersede it within their scope — `FP-002` for token lifecycle
      and claim content, `FP-003` for tenant lifecycle and authentication eligibility, and any other
      the sweep finds — and declaring the remainder deferred and non-authoritative until covered.
- [ ] **The expired-subscription login rule points at `REQ-SUB-0018` rather than restating it.**
      `OD-SUB-0009` made it binding and FP-014 owns it now; two copies of a ruled rule is how they drift.
- [ ] **Sweep before you write.** Read the whole file and list, in the result, which sections are
      superseded and which are genuinely still the only statement of their subject. Do not assume the
      split — `Tenant-Management.md` names its superseded topics explicitly and that precision is the
      point.
- [ ] `status:` is **not** changed to `Approved`. It stays `Draft`, now with an accurate account of
      what that means for each part. If the sweep shows the whole file is superseded, **say so and stop** —
      that is a different task and a bigger claim.
- [ ] `git diff main...agent/T-012-authentication-disclaimer --stat` shows **exactly one file**.

## Design constraints

- **Match `Tenant-Management.md`'s block closely** — same position, same voice, same explicitness about
  which topics move and which stay. A second dialect of the same disclaimer is worse than one.
- **Name packages, not adjectives.** "Superseded by approved FP-002 for token lifecycle and claim
  content" is checkable; "largely superseded" is not.
- **`DEC-L-022` applies to the sweep list**: if you cannot be exhaustive, say the list is what you
  found rather than implying it is complete.
