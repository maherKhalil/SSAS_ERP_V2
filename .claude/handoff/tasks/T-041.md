# T-041 — The trial: an all-module plan with a 14-day term

- **Branch:** `agent/T-041-trial-seeding` — branch from `main`
- **Module:** Platform (commercial plane)
- **Issued:** 2026-08-26
- **Depends on:** T-040 merge (PR #83). **Gated.**

## Goal

T-040 made the resolver real, and a tenant with no subscription now reaches no gated module. **This is
the task that stops that being a lockout.**

`DEC-L-034`: a tenant without a subscription gets an **all-module plan with a 14-day term**, seeded by
the cutover migration for the existing estate and on tenant creation thereafter. `OD-SUB-0014` already
ruled that a trial **is a plan with a short term — not a state, not a flag**, so this introduces no
new concept and must not invent one.

`DEC-L-033`: when that term ends the tenant **loses gated modules and keeps login**. T-040 already
implements that; this task must not re-implement it.

## Acceptance criteria

- [ ] **A seed migration gives every tenant existing at cutover the all-module plan with a 14-day
      term.** Unlike `AddSubscriptionCommercialPlane`, this one **does** write rows — say so plainly in
      the file, since its predecessor's `THROW` exists to catch exactly that.
- [ ] **Tenant creation issues the same plan and term.** One rule for existing and new tenants
      (`DEC-L-034`), so there is one thing to explain to a customer.
- [ ] **The trial is the plan, not a state.** No `IsTrial`, no fourth lifecycle value, no flag. If the
      model tempts you toward one, **that is a finding about the model** — report it rather than adding it.
- [ ] **Re-running the seed does not double-issue.** A tenant that already has a subscription is left
      alone. Prove it: run the seed twice in a test and assert one subscription.
- [ ] **`DEC-L-039` applied to the two `DEC-L-027` instances T-040 created** —
      `ModuleEnablementGateTests.cs:17` is a test comment describing the present, so **correct its
      tense**; `AddSubscriptionCommercialPlane.cs:22` is a migration, so **stamp the claim with the date
      it was true and leave it standing.** The difference between the two treatments is the ruling.
- [ ] Gate green under `DEC-L-008`, **Integration runs against real SQL** — a real seeded tenant
      reaching a gated route, and an expired one refused while still authenticating. Merged on green.
      Baseline: Architecture 474, Platform 1025, API 718, HR 326, Finance 46, Payroll 56,
      Attendance 59, **Integration 796 both configurations**.

## Out of scope

- Seat caps, metering, invoicing, payment. `ADR-029` still forbids any field capable of holding
  cardholder data.
- The administration surface to create plans or assign subscriptions — a real plan is still assigned
  by nobody, which is why the trial exists.
- Distributed cache invalidation (`T-042`) and the reference policy (`T-033`).

## Design constraints

- **14 days is short for an ERP and that is the owner's ruling, not an oversight.** Do not soften it,
  and do not add a grace period — `DEC-L-009` ruled none, and `DEC-L-033` bounds the consequence to
  modules rather than the door.
- **The seeded plan is a real plan and must look like one.** A future administration surface will list
  it beside plans someone actually bought, so it needs a name a human reading a plan list understands.
- **Do not backfill history.** The subscription is append-only and monotonic; seeding writes the first
  record, it does not reconstruct a past.
- Where the seed and `AddSubscriptionCommercialPlane`'s `THROW` interact, **say how** — one refuses
  rows, the other writes them, and a reader needs to see that the ordering is deliberate.
