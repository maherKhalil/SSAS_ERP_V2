# PART 1 — reachability, re-run under `DEC-L-069`

**The rule landed mid-task and it applied to me.** Every claim below was re-run with **no `head`**, counts
first. Two of my earlier searches had carried limits.

## Reachable — five, and each has one specific request that produces it

```
Employee.PositionRequired     positionId = 00000000-0000-0000-0000-000000000000
                              a WELL-FORMED Guid string, so it passes transport and reaches
                              `positionId == Guid.Empty` (CreateEmployeeCommandHandler:222)
Employee.PositionNotFound     an unknown positionId -> FindAssignablePositionAsync returns null
Employee.PositionInactive     a position that exists with IsActive == false
Employee.PositionUnchanged    change-position to the position the employee already holds
EmployeeImportRun.InvalidImportKey   an overlong importKey on POST /import
```

**The all-zero Guid is the only door to `PositionRequired`.** The route requires `positionId` and demands
a JSON string, so a missing or null one is refused at transport before any handler runs. Without that
one path the error would be unreachable and would belong in the list below.

## Unreachable — eight, for **three separate reasons**, none of them an oversight

**BY DESIGN — four.** `PositionHistoryImmutable`, `InvalidCounts`, `InvalidColumnSet`, `InvalidActor` are
500 *because* a caller cannot cause them. A test would have to manufacture the state and would assert
the manufacture rather than the contract. **This is the ruling being self-consistent, not debt.**

**BY DEAD CODE — three.**

```
Employee.PositionInDifferentCompany   ZERO raise sites. Three occurrences in the whole repository:
                                      its declaration (EmployeeErrors.cs:155-156) and its arm.
Payroll.PayElementOvertimeTierInvalid       raised only inside PayElement.SetOvertimeTier (:350, :356),
Payroll.PayElementOvertimeTierNotApplicable  and SetOvertimeTier has NO caller in src/ — unlimited
                                             grep returns only its own declaration at :344.
```

**BY NORMALISATION — one.** `InvalidFileName` cannot fire from the route. `TryFileName`
(`EmployeeEndpointRouteBuilderExtensions.cs:836-869`) defaults to `"import.csv"` when the header is
missing, empty or has an empty leaf; **returns false on control characters before the handler**; and
**truncates to 260**. The value reaching the aggregate is always non-empty and within the cap.

**The aggregate keeps its check anyway and is right to** — it is not the aggregate's business to rely on
a route's normalisation. **Unreachable-from-here is not the same as unnecessary**, and collapsing the
three reasons into one word would have lost that.
