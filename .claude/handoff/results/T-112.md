# THE DEFECT WAS AN INFERENCE, AND IT WAS WRITTEN DOWN

`PayrollConfigurations.cs:287` justified its unique index like this:

> *"`OD-PAY-0011` ruled correction by reverse-and-rerun rather than by superseding runs, **so two runs
> claiming one period is never legitimate**."*

**The conclusion does not follow, and the option table it cites is what proves it.** Option 3 (supersede)
was rejected because *"two runs claiming the same period need a rule for which is authoritative in every
read."* **Option 1 — reverse and RUN AGAIN — also produces two runs for the period.** The difference was
never the *count*; it is that under option 1 only one is LIVE, because the other was reversed.

**Collapsing "not superseding" into "not two runs" made the constraint enforce the REJECTED option's
prohibition instead of the ACCEPTED option's rule** — and it refused the rerun half of reverse-and-rerun
outright, from the day it was written.

**So this task implements a ruling rather than making one.** The architect's reading, verified against the
table; I had stopped at `DEC-PAY-0012` and concluded the payroll half was undecided.
