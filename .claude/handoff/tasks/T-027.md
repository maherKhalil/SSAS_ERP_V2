## Goal

Your observation is now `DEC-L-027`: **a task that changes the world must check whether it falsifies
the document describing that world, and the likeliest casualty is the file it just edited.** Three
instances in one day — `README.md:17` after T-024, closed concern 3's present tense after T-021, and
`business-rules.md`'s header after T-022.

This task is that rule applied to everything FP-014's ratification left describing the world before it,
in one diff instead of three repairs. It also adds the two things ratification was always going to owe:
the roadmap entry, and the `status:` key FP-014 is the **only** package missing.

## Acceptance criteria

- [ ] **`business-rules.md`'s header block has its tense changed, not its content removed.** Every
      clause of *"THESE RULES ARE NOT IN THE MASTER REGISTER… `SUB` is in neither… this package does
      not perform it"* is now false. But the middle of that block explains **why promotion belongs to
      ratification and how `BR-PAY`/`BR-ATT` were lost** — still true, and the argument `DEC-L-012`
      rests on. Keep it; say it happened rather than that it must. The title *"Proposed business rules"*
      and the heading *"## Proposed rules"* carry the same staleness.
- [ ] **`README.md` gains a `status:` front-matter key** in the shape FP-001…FP-013 use, recording the
      package as ratified with its date. FP-014 is currently the only package without one — the same
      defect T-004 fixed for FP-012 and FP-013.
- [ ] **`README.md`'s title no longer reads "(analysis package)"**, which was true at T-002 and is not
      now. Its status line should record what is and is not done: ratified, registers promoted, **no code**.
- [ ] **`Product-Roadmap.md` gains the commercial plane.** It runs to Version 5 and names subscription,
      billing, plans, metering and signup **nowhere** — while `CON-0001` says the product *shall* be
      subscription-based SaaS and FP-014 now specifies it in full. Place it where the owner's `E + C`
      ruling puts it, and **say in the result why you placed it there**; that judgement is worth seeing.
- [ ] `trace-check` **full run byte-identical** to the T-028 baseline, FP-014 **GREEN `0 unruled`**.
      Prose changes must move no identifier and no count.

## Design constraints

- **The roadmap entry is a product statement, so keep it to the roadmap's own register** — one line in
  the style of its neighbours, not a summary of FP-014. The roadmap names capabilities; the package
  specifies them.
- **Do not claim the commercial plane is built.** It is specified and ratified with no code. A roadmap
  entry that reads as delivered would be the same defect this task exists to fix, committed fresh.
- Where a sentence was true at a point in time, prefer marking *when* it was true over deleting it —
  the pattern FP-013's RATIFIED banner established and T-024 used.
