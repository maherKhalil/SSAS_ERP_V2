## One enumeration, two guards

As instructed, and the reason matters more than the tidiness: **two enumerations are two things that
can drift**, which is the shape this pair of tasks exists to remove.

`RequiredPermissions()` now yields `(Route, DeclaredScope, Permission)`. **`DeclaredScope` is the scope
the POLICY PREFIX declares, not one read from the catalog** — the prefix is how the plane is chosen
(`PermissionAuthorizationPolicyProvider.cs:14,19` dispatches on exactly it), so it carries the endpoint
author's stated intent, and the catalog is the thing it is then checked against. Both guards read the
same array:

```
the join    does this name EXIST?                       T-072
the scope   can the caller this route is for HOLD it?   T-073
```

**Both failures look identical from outside** — a route that refuses every caller while every line of
it reads correctly — and both facts needed to tell them apart were already in the tree, never compared.

## What the message says and does not say

The failure names the disagreement and no remedy. **Which of the two is wrong — the plane the route was
mapped on, or the scope the permission carries — is an authorization decision**, and a test asserting
that one of them was the correct half would be claiming a cause it cannot know. That is the defect
recorded repeatedly on this board and the reason every message in this file states a question.
