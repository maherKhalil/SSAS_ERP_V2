# ⚠ BUCKET 3 — 63, AND MY DEFINITION CONFLATED TWO DIFFERENT THINGS

**Most of the 63 are `1/12`: a module's own code, named in that module's own mapper. That is the healthy
state, and my bucket called it "partial".**

**The discriminator is not how many mappers name a code. It is whether the OWNING CLASS is reachable from
more than one module.** By that test, sixty-two of the sixty-three are module-local and correct.

## ⚠ FIRST — WHICH CODE THIS ANALYSED, BECAUSE THERE ARE TWO ONE WORD APART

```
Authorization.Unauthorized   IdentityAccessErrors.cs:57    5 mappers   ANALYSED BELOW
Tenant.Unauthorized          TenantLifecycleErrors.cs:14   4 mappers   NOT ANALYSED — out of scope
```

**Different codes, different declarations, different mappers.** `Tenant.Unauthorized` is declared in a
`*Errors` class, which this sweep's criterion excludes by design — **the twenty-three are static classes
that RETURN errors, not the classes that DECLARE them.**

**It is out of scope rather than missed**, and it was separately found and fixed earlier when it was
unmapped at four Platform sites. **Named here because the conclusion below says "none of their codes is
currently a 500", and a reader meeting two near-identical names would take that as covering both.**

## The one genuinely shared class, and its five omissions are RIGHT

```
Authorization.Unauthorized   from ApplicationExecutionContext   5 of 12 mappers
  named by      Company, IdentityAccess, Localization, PlatformSupportAuthority, Employee
  NOT named by  Attendance, GL, Payroll, Department, Position
```

**This is your `Tenant.Unauthorized` shape exactly, and it is not a defect: `ApplicationExecutionContext` is
used ONLY within Platform.** No module references it, and `Authorization.Unauthorized` is returned from
exactly two files, both Platform. **The five mappers that omit it cannot reach it.**

## And one dead arm, in the other direction

**`EmployeeApiErrorMapper` names `Authorization.Unauthorized` and HR cannot reach it** — HR names
`AuthorizationErrors` nowhere, and the code is returned only from Platform.

**Reported, not removed.** A dead arm is harmless where a missing one is a 500, and removing it is a claim
that nothing will ever route HR through that context. **T-095's lesson pointing the other way.**
