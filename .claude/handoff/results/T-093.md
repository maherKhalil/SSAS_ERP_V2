# THE FINDING OUTRANKS THE DEFECT

`Tenant.Unauthorized` is returned by `ApplicationExecutionContext.GetTenantActor`, **which every
tenant-plane handler funnels through.** It was unmapped at all four Platform sites:

```
Company, PlatformSupport   -> 500   an authorization refusal reported as a SERVER ERROR
IdentityAccess, Localization -> 400 the same refusal blamed on the CALLER
```

`EmployeeApiErrorMapper`'s header states the rule this violated: *"a refusal reported as a server failure
tells the caller to retry something that will never succeed, and pages an operator for a working system."*

**`Every_platform_site_answers_a_tenant_authorization_refusal_with_403` asserts all four together**, because
the property that matters is that they AGREE — a caller must not learn which surface refused them from the
status code.

## Decisions worth a person's attention

### The register asserts an arm exists and NOT which status it gives

So it would have stayed green with `Common.NotFound` mapped to 400. **The defect T-091 shipped was a wrong
ANSWER, not a missing arm**, and the register alone cannot see the difference. `PlatformErrorMappingTests`
pins the ruled answers; the register keeps the debt honest. Two guards, two properties.

### Four families have no HTTP surface, recorded rather than left looking like a hole

`Branch`, `Subscription`, `TenantStorage` (117 codes) and `UserEmployeeLink` are declared and reachable from
no route. **`UnroutedFamilies` is a DECLARATION on the same footing as `ResponsibleFamilies`**, and for the
reason the file already gives: there is no call graph to walk. It is an exact set with a staleness check
both ways — a family listed that no longer declares anything also fails.

### The strings I picked, reported as instructed

- **403s** use `ProblemResults.Forbidden`, which is an **alias of `ApiErrors.Forbidden`**, not a second
  definition. Not a deviation — it is Platform's spelling of the same object.
- **Localization cannot reuse the object at all**: it projects its own `LocalizationApiError` type. It
  reuses the **code string** `authorization.forbidden` instead, so the same refusal does not look like two
  different ones depending on which route answered.
- **`platform.not_found` / `platform.transition_invalid` / `platform.unique_conflict`** at IdentityAccess,
  deliberately not resource-specific: that mapper answers for roles AND tenant users, so
  `tenant_user.not_found` would be a lie on the roles route.
- **`localization.unique_conflict`** follows its site's `localization.*` convention.

### Authentication is registered as a site, not omitted

Every ordinary authority failure collapses to one generic 401 by ruling, asserted by
`Every_ordinary_authority_failure_returns_the_same_generic_401`. **All eighteen codes are listed in
`KnownUnmapped`.** An omitted site is indistinguishable from an oversight; a registered one means a new
authentication error has to be written down by a person, who meets the reasoning while doing it.

### The register declares its own floor, with the two demonstrations

Not asserted in the abstract. The header names both: the manual walk missed `TenantUser.InvalidTransition`
— a code already known reachable, arriving as `domainResult` rather than through an `*Errors.*` symbol —
and it put Company at one when the register found five more. **T-094 replaces the static handler set with a
transitive walk; when it lands these exact-set registers go red and force the work.**
