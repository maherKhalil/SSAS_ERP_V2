# WHAT DAILY COMPUTES

```
DAILY = rate x (standard working days - unpaid absent days)
```

**And the rejected model is named in the code**, because `"daily rate"` invites it: `rate × days ACTUALLY
worked` excludes absence already, so the `UnpaidAbsenceDeduction` element would take it a second time —
the double-count the hourly path avoids by taking no deduction at all.

**The owner's own contrast is what settles it.** They excluded HOURLY from that deduction *because an hourly
employee is paid only for the time they attend*, and INCLUDED daily. **That contrast is only meaningful if a
daily employee is not paid solely for time attended.**

**Both apply, and that is the model rather than an oversight:** 22 working days less 3 unpaid is 19 at 200 =
3800 of base, and the deduction then prices those 3 days at the calendar-day divisor it has always used —
3800/31 × 3 = 367.74. **The base answers "how many days is this employee owed"; the deduction is an element
a company configured. Different questions.**

**Clamped at zero.** More unpaid days than the period holds is bad data, and a negative base would flow into
every percentage element and produce a payslip that is arithmetically consistent and nonsense.

# ⚠ THE INFERENCE DAILY INHERITS, NAMED WHERE IT HAPPENS

`GetForCompanyAsync` returns the **default** calendar, falling back to the alphabetically first.

**A company with an office calendar and a plant calendar gets one of them** — and already does, because
**leave freezes its consumed days against exactly this resolution**, and a leave day-count drives unpaid
absence, which drives a deduction. **The inference is already load-bearing for money.**

**Daily pay inherits it rather than introducing it.** Refusing it here while leave keeps doing it would
break daily pay for every multi-calendar company and offer nothing better. **The real answer is an
employee→calendar assignment and it does not exist anywhere in the product** — written into
`AttendanceSummaryService` where the resolution happens, not filed elsewhere.
