# 1. WHERE IT LIVES — `trace-check.py` gains a mode; `gate.sh` calls it

**Recommended, and the split is not arbitrary: each file already owns exactly one half.**

**`trace-check.py` owns every identifier fact** — `ID_RE`, `HOME_FILES` (`:131-138`), the per-package
convention overrides, `homes_for()`, and `CITATION_ROOTS` / `CITATION_SUFFIXES` (`:370-376`), which already
answer *"where may a citation live"* with `.cs` deliberately included.

**`gate.sh` owns the diff, and its source is already right** (`:1235-1246`):

```bash
BASE=$(git merge-base HEAD "$REF")     # REF = origin/ClaudeBranch
git diff "$BASE" -- src/               # no second commit -> compares BASE to the WORKING TREE
```

**The working tree is included deliberately, and the header says why** (`:190-191`): uncommitted work counts,
and a merge-base-to-HEAD diff would see nothing before the first commit. **That is exactly what an advisory
needs** — it should fire while you are still editing, not after you commit.

**So: `gate.sh` computes `BASE` and calls `trace-check.py --citers "$BASE"`.** Reimplementing the identifier
grammar in bash would be a second copy of the one thing `DEC-L-080` forbids — **inside the instrument built
to detect that failure.**

# 2. IS THE DISCRIMINATION REUSABLE? THE CONCEPT YES, THE IMPLEMENTATION NO — AND IT OVER-REPORTS

**`trace-check.py:656-660` is the whole of it:**

```python
for ident in scan_ids(text):
    cited[ident.space].add(ident.key)
    if fname in homes_map.get(ident.space, ()):
        defined[ident.space].add(ident.key)
```

**The discrimination is by FILE, not by line.** An identifier counts as defined if it appears **anywhere in a
home file**. There is no line-level notion of a definition anywhere in the script. **It cannot answer "did
THIS line define something", and no amount of reuse will make it.**

**What IS reusable is the concept and its data** — `HOME_FILES`, `homes_for(package)`, `ID_RE`. Per changed
line: *is this line in a home file for this identifier's space, in the package that owns it?* Cheap, and
correct as far as it goes.

## And the over-report already has a name in this loop

**A CITATION sitting inside a home file is indistinguishable from a DEFINITION.** Not hypothetical:

```
docs/17-features/FP-013-attendance/acceptance-criteria.md:120
  a prose citation of `AC-ATT-0032`, inside AC's own home file
```

Editing that line fires the advisory. **`DEC-L-074` one layer down, in the instrument: the sweep cannot tell
a claim from a quotation of a claim.**

**For an advisory that reports and never fails, over-reporting is the correct direction to be wrong** — but
**the output must say only what it actually knows:**

```
say:   "a line in AC-ATT-0032's home file changed and names it — here are its citers"
NOT:   "AC-ATT-0032's definition changed"
```

**The wording IS the honesty.** `DEC-L-070` — the instrument cannot be the evidence about itself, so it
states what it saw rather than what it concluded.
