```
DEC-L-056    **restricts:** `MSYS_NO_PATHCONV`
```

**Both were applied and verified before being reverted**, so this is a tested pair rather than a
suggestion: with them in place the check attributes `git ls-tree` to `DEC-L-054b` and
`MSYS_NO_PATHCONV` to `DEC-L-056`, and a planted third rule prescribing `MSYS_NO_PATHCONV` collides

**Liveness is the presence of the key.** `DEC-L-054` carries no key because `DEC-L-054b` replaced its
mechanism — **losing the key is how retirement is expressed**, and that is why there is no supersedes
graph. It is the cheapest thing that answers *"when I restrict X, what already depends on X?"*

The report prints the **deduplicated set of mechanism strings** so a typo — which would otherwise fail
to join in silence — surfaces as a near-duplicate to a human.

## Three defects in the decision register itself, and they matter to Part B

**The register is not a text file.** `file` reports `data`; `grep` without `-a` prints
*"Binary file BOARD.md matches"* and **no lines at all** — on the file whose whole design premise is
*"the grep must be a grep and not a parser."*

```
NUL bytes (0x00)                  : 2      written where the TEXT `\0` was meant
lone CR (0x0D not followed by LF) : 5      written where the TEXT `\r` was meant
```

Both are control characters typed where their **escape sequences** were meant, inside entries
describing git's blob header and a mangled Windows path.

**The lone CRs produced a wrong answer that looked right.** `Path.read_text()` applies universal
newline translation, so a bare CR becomes a line break: the `DEC-L-054b` row was split in two, and its
`prescribes:` key was attributed to **`DEC-L-054`** — the id appearing in the second fragment, and the
one whose mechanism had been *replaced*. **A register check confidently naming the retired rule as the
live one.** The checker now reads bytes and decodes.

**And my first fix was the wrong mechanism.** I blamed `str.splitlines()`, which does split on a lone
CR — a true statement about CR that was not what was happening, because the translation had already
converted it. **The partial reason again: the first thing I checked confirmed it.**
