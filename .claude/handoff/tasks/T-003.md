# T-003 — ADR: the identity → employee link

- **Branch:** `agent/T-003-adr-identity-employee` — branch from `main`
- **Module:** Platform + HR (architecture)
- **Issued:** 2026-08-25
- **Depends on:** T-017 merge

## Goal

Two delivered packages stopped at this exact wall. `REQ-ATT-0023` is marked *BLOCKED — NOT
IMPLEMENTABLE TODAY: it needs a mapping from the authenticated identity to an employee record, and no
such mapping exists*. `OD-PAY-0016` deferred payroll self-service for the same missing input. The
whole Self Service roadmap item sits behind it.

I have ruled the shape (`DEC-L-023`). This task records it as an ADR — it binds Platform, HR,
Attendance and Payroll, and cannot be revisited cheaply, which is this repository's own test for when
an ADR is warranted.

**This is the ADR only.** The feature package that builds it is separate and comes after.

## Acceptance criteria

- [ ] An ADR records the ruling: the link is a **Platform-database mapping keyed by tenant**, holding
      the `TenantUser` and the `Employee` it names. **`Employee` gains no column and `TenantUser` gains
      no column.** Optional on both sides; at most one live link per user and per employee.
- [ ] It states plainly that **no foreign key exists in either direction and none can** — the two rows
      live in different databases — and names the precedent that makes this acceptable rather than novel:
      `ADR-017` already accepts `CreatedBy`/`ModifiedBy` as plain scalar identifiers with no foreign key,
      and `DEC-SUB-0009` settled no-cross-database-FK for FP-014.
- [ ] It gives the three reasons, because a future reader will otherwise propose the column: `ADR-017`
      puts tenant identity/access membership in the Platform database deliberately and this is an
      identity fact; the relationship is **optional on both sides** so nullable columns on two aggregates
      could disagree; and `Employee` is in the Shared→Dedicated cutover inventory while `TenantUser` is
      not, so either column would break at cutover in a different way.
- [ ] It names what it does **not** decide — whether the link carries history, how a link is created and
      revoked, what happens when an employee is archived or a user deactivated, and whether self-service
      permissions are distinct from delegated ones. Those are the package's, not this ADR's.
- [ ] `status: Accepted`, dated today, and **the number confirmed unclaimed** the way T-010 confirmed
      029. `ADR-030` is the expectation; verify before taking it and say so in the result.
- [ ] `git diff main...agent/T-003-adr-identity-employee --stat` shows **at most two files**, both under
      `docs/14-Engineering/ADR/`.
