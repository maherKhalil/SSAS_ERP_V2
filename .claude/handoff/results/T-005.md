### The check

**`ORPHAN` / `UNTRACED` (7a, 7b).** Definitions are read from `Constraints.md` (`## CON-####`) and
`Business-Rules.md` (`## BR-###-####`). Every other file in `docs/`, `src/`, `tests/`, `tools/`,
`scripts/` and `.github/` is split into blocks by the script's existing `split_blocks`, and a rule is
**cited** if any block names it and **traced** if any such block also carries a `REQ-` identifier.

- **The tracing signal is co-occurrence within a block** — the same signal checks 3 and 4 already use
  for the chain table. Reusing it means the two cannot disagree about what a link is.
- **The corpus is wider than `docs/`** on purpose. A constraint satisfied by a comment in a `.cs`
  file *is* traced, and refusing to look there would manufacture orphans. `BR-PLT-0014` is a live
  example: its only non-`docs` citation is `tests/Integration.Tests/BranchTransferBoundarySqlServerTests.cs`.
- **The definition files are excluded whole**, not filtered per-identifier. A rule's own heading is
  not a citation of itself, and neither is the paragraph under it — excluding the line but keeping
  the body would count the rule's own text as evidence that something references it.
- **One pass over the corpus, not one per identifier.** 73 identifiers against 1,575 files inverted
  the other way is a product this script should not pay. Whole run: **0.6 s**.

**`UNPROMOTED` (7c).** For each package's `business-rules.md`, the `BR-<MODULE>` spaces it defines
are compared against the modules the master file carries. A package citing one or two rules of a
foreign module is quoting a neighbour, not owning a space, so the floor is **three** — the same floor
`own_modules()` already uses, for the same reason, so the two rules cannot disagree about ownership.

**Exit codes.** `0`, `1` and `2` keep the meanings they have always had, so a caller testing `== 1`
is untouched by check 7. New code **`3`** means *every package clean, master register has findings* —
a caller testing `!= 0` sees it. A package failure still wins and returns `1`.

**`--no-master`** runs checks 1–6 only.

**One behaviour change beyond added output, flagged rather than buried:** with `--json`, the payload
is now `{"packages": [...], "master_register": {...}}` instead of a bare list. I checked before
changing it — `trace-check` is referenced by nothing in the repository except `.claude/handoff/`
documents, so nothing consumes the old shape. `--no-master --json` still emits `{"packages": [...]}`
with no second key.
