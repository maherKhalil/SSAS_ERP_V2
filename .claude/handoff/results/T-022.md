## Three judgement calls, stated because each could have gone otherwise

**1. Which section shape.** The master file has **two**. Older rules (`BR-GL`, `BR-HR`) are
`## BR-####` followed straight by the statement; later Platform rules add `### Title`, and
`BR-PLT-0016` goes further with `### Description`, `### Applies To`, `### Priority` and
`### Related Requirements`.

I used **`BR-PLT-0008`'s shape** — `## BR-SUB-####` / `### Title` / name / statement — which is what
your spec described. I deliberately did **not** use the fullest form: `### Priority` would have meant
inventing a criticality judgement for 21 rules that FP-014 never made, and `### Related Requirements`
would have added citations that could perturb check 7's `ORPHAN`/`UNTRACED` arithmetic — the very
output this task is measured on.

**2. Titles are new text, and the file says so.** The 21 titles do not exist in FP-014; a title is a
summary, and a bad summary of a ruled rule is the same hazard as a paraphrase. So they are plain noun
phrases echoing each rule's own words, and **the section header states that the statements are FP-014's
and the titles are labels added here**, with a link back for each rule's authority.

**3. Terminal punctuation left alone.** FP-014's table cells carry no closing full stop; every existing
rule in `Business-Rules.md` does. **I left the 21 statements exactly as written**, so they end without
one. A full stop changes no meaning and I could defend adding it — but "verbatim" that quietly
punctuates 21 rules is not verbatim, and this is trivially reversible if you would rather have it.
