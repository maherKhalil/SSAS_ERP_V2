## What changed

Three files, 456 insertions, no deletions.

### The decision: where the guard hangs

`PlatformDbContext` overrode only `SaveChangesAsync(CancellationToken)`. Its own base class documents
why that is not enough:

> "EF Core's own chain is `SaveChanges()` -> `SaveChanges(bool)` and `SaveChangesAsync(ct)` ->
> `SaveChangesAsync(bool, ct)`, both by virtual dispatch. Overriding only the convenience overloads
> … leaves … `SaveChangesAsync(bool, ct)` writing without audit stamps or the tenant-ownership guard."

`TenantDbContext` reaches full coverage differently — async funnel calls the guard, synchronous
overload throws outright for cutover reasons that do not apply to Platform. So Platform fences **both
innermost overloads**. **What is mirrored is the property that no path bypasses the rule, not the
line count**, and two of the six tests exist solely to prove the fence point — one per bypass route.

### The test entity, and the line I did not cross

No production Platform entity implements `IAppendOnlyEntity` and none was added. A test-only probe is
injected into the **real** `PlatformDbContext` model through a replaced `IModelCustomizer`, so the
guard under test is the production one on the production context. Only the two probe tables are
created rather than the whole Platform schema — `EnsureCreated` would translate every Platform
configuration into SQLite, and a provider mismatch reported as an append-only failure would be a
worse test than none.
