# THE FINDING THAT STANDS REGARDLESS

**`trace-check` cannot see a `.cs` citation of an identifier defined nowhere.**

The orphan rule walks identifiers cited in the package's **own `.md`** files (`pkg_dir.glob("*.md")`). `.cs`
is in `ALLOWED_SUFFIXES` for the global index — so a `.cs` comment counts as a citation **of a defined
identifier** — but nothing walks `.cs` for citations of identifiers defined **nowhere**.

**A fabricated identifier in code reports nothing.** `DEC-L-078` in the checker's own coverage.

**And the corollary is the load-bearing half:** the rule fires the moment markdown cites the identifier — so
**writing the citation you asked for is the only thing that would have surfaced this.** True whether or not
this particular instance turned out to be a divergence.
