# WHAT THE WALK FOUND, AND WHY THE OLD REGISTER COULD NOT

```
DepartmentApiErrorMapper                 10  Employee.*
PositionApiErrorMapper                   10  Employee.*
EmployeeImportExportTransportContracts    6  Employee.*
PlatformAuthentication                    6  Authentication.* + Persistence.ConcurrencyConflict
PayrollApiErrorMapper                     1  Gl.AccountNotFound
```

**`Department` and `Position` answer 500 today for ten employee-shaped refusals each.** Their routes invoke
`ChangeEmployeeDepartmentCommandHandler` and `ChangeEmployeePositionCommandHandler`, which return
`Employee.*` directly. Under `ResponsibleFamilies` those sites owned `Department` and `Position` and nothing
else, so **no arrangement of the old register could have seen this.**

**`Payroll` answers 500 for `Gl.AccountNotFound`**, returned through `IJournalPoster` when the mapped account
is gone — a GL code reaching a Payroll mapper, which is the cross-module case this file's own header already
described and the family register could not reach.

**This is T-079's finding recurring ACROSS families rather than within one.** T-079 found a code mapped for
one HR surface and not for the one that raises it; this is the same defect where the two surfaces belong to
different modules.

# `DEC-L-078` APPLIED TO THE TOOL THREE TIMES WHILE IT WAS BEING BUILT

Every one was the same shape, and **not one reported an error:**

1. **A lost regex escape.** The type-declaration pattern ended up holding a literal backspace character
   where `\b` was intended, so the source index matched nothing and every site's responsible set was empty.
2. **Test doubles in the closure.** `ProductTypes()` filtered on the `SSAS.` prefix, which also matches the
   test assemblies — `GuardClock` implements `IDateTimeProvider`, so the walk climbed into test code.
3. **A closure that depended on load order.** `AppDomain.CurrentDomain.GetAssemblies()` returns only what
   the runtime has loaded so far. **Five red sites under a filtered run and ten under the full suite, from
   identical source.**

**All three were caught by the non-vacuity assertion and the unlocated-type guard**, which is the entire
argument for writing those before trusting a number. The third is now impossible: assemblies are reached
from the seeds and closed over their references explicitly, so the answer does not depend on what ran first.

**The pattern lives in a named constant now**, because an editing accident that leaves a control character
inside a verbatim string reads as a word boundary and produces a quieter answer rather than a failure.

## The numbers moved differently from the Part 1 estimate, and that is the point

Part 1 measured with source text and predicted ~19 `TenantStorage.*` codes at each tenant-writing site.
**Under reflection they do not appear.** Company, IdentityAccess, PlatformSupport, Localization, Attendance,
GL and Employee all derive to fully-mapped sets.

**The Part 1 numbers were labelled a source-text approximation and they were one.** The reflection result is
the authoritative one, and the disagreement is in the direction `DEC-L-078` predicts for the *other* tool:
the text walk resolved a different closure and counted codes the reflection walk does not reach.

**I am not claiming the TenantStorage codes are unreachable** — floor 2 says the register cannot prove
either way. What changed is that nothing now asserts they are responsible, and the earlier claim that
`UnroutedFamilies` was hiding them was made on the weaker tool.

## The four floors, stated in the header as a replacement

1. **Route → mapper is still declared.** No call graph, no Roslyn. `Seeds` is that declaration.
2. **A returned error is not a reached error.** *The replacement for the old floor.* The walk proves a
   closure type RETURNS a code; it cannot prove the code propagates rather than being handled in between.
3. **Inline-constructed codes are invisible.** Only `SomeErrors.Member` is extracted; Localization's
   vocabulary is string literals.
4. **Which implementation DI actually binds.** The walk follows every implementor, so the closure is a
   superset where an interface has several.

**Floors 1, 3 and 4 predate T-094. Floor 2 is new because the old one was replaced, not closed** — the
header says so, so it cannot later read as though T-094 closed something it moved.
