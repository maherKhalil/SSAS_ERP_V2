## The convention adopted is FP-013's, deliberately

`**RULED: <the answer>**` on the line below the heading, seventeen times. **`OD-SUB-0014`'s
heading-level marker is gone.** The older convention wins because it predates T-036 by a
ratification, and the only reason the newer form existed is that nobody looked — which was the
point of the task rather than a detail of it.

**Every marker states the answer**: `RULED: 403 FORBIDDEN`, `RULED: APPEND-ONLY HISTORY, exactly
one in force at a time`, `RULED: SEATS PLUS LIMITS`. A marker saying only *"ruled"* sends the
reader to a second file for the thing they came for, which is the original defect in miniature.

**The two amended rulings carry their amendments in the marker itself.** `OD-SUB-0009` names
`DEC-L-033`'s expiry change, `OD-SUB-0010` the mechanism correction, `OD-SUB-0014` `DEC-L-034`.
Stopping at a marker is a legitimate way to read the register — that is what a marker is for — so
a reader who stops must not come away with the superseded answer.

## `DEC-L-043` where there was no contradiction to chase

**17 of 17 was exactly what I expected, so the trigger never fired.** The rule as written had

**So the question became: what would make this green hollow?** Check 8 accepts a
ratification-file **link** as an acknowledgement as well as the token, and `OD-SUB-0014`'s block
contains such a link — **so that package could have passed with no marker at all.** That is the

Read out of `--json` rather than trusted: **all seventeen matched `RULED`; none matched the link

The generalisation, which is narrower and more usable than "verify a suspicious green": **when
there is no contradiction to chase, name the specific way the pass could be hollow and rule that
one out.** *"No contradiction, therefore nothing to check"* is how a rule with a real trigger
still fails to protect you.

## A finding about editing this repository at all

**My first `perl` substitution to strip the heading-level marker reported success and changed
nothing.** It exited 0 and applied to zero lines.

**The cause is CRLF.** The `$` anchor cannot match with `\r` before end-of-line, and this
repository is full of CRLF — git has warned about LF→CRLF conversion on nearly every text file
touched today. Dropping the anchor applied it.

**A substitution that silently matches nothing is the same failure shape as a guard that never
fires.** Both report success; both did nothing; neither is visible without checking the count
rather than the exit code. **Any anchored regex edit in this repository needs its match count
verified, not its exit status.**
