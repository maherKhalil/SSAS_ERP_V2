## Part D — the one that matters, demonstrated rather than argued

**A build that did not compile reported `[GATE GREEN]` and exit 0.**

```
Build FAILED.
  ErrProbe.cs(3,72): error CS0029: Cannot implicitly convert type 'string' to 'int'
  1 Error(s)
Passed! 509 · 1032 · 326 · 724 · 46 · 56 · 59      <- the PREVIOUS build's assemblies
[GATE GREEN -- TASK scope: seven suites, NO Integration, Debug only]     exit 0
```

`dotnet build`'s status was **computed and discarded** — `grep` ran on the next line, so `$?` was
grep's, and `GATE_FAILED=1` was set only inside the suite loop. The suites then ran `--no-build`
against whatever was last built successfully, passed, and carried the run to green.

**`DEC-L-007` makes this exit code merge authority, so the gate was prepared to merge code that does
not compile.** It is note 3's own defect — a condition computed and thrown away — moved from the
verdict to the build, and found the day after the same shape was found in the memory sampler.

**After:**

```
!!! BUILD FAILED (Debug) -- dotnet build exited 1.
!!! Suites SKIPPED for this configuration: --no-build would run the PREVIOUS build's
!!! assemblies and, if those were green, report green for code that does not compile.
[GATE RED -- TASK scope: ...]     exit 1
```

**No suite lines at all.** Running them would produce a green describing a build nobody performed.

## Part A — the mechanism question answered itself

**Baseline, cold builds in a fresh worktree: `Debug 0 warnings`, `Release 0 warnings`.** Adoption cost
nothing.

Then the measurement that decided the mechanism:

```
plant one CS0219, build      ->  1 Warning(s)
build again, nothing changed ->  0 Warning(s)      <- the warning is still in the code
--no-incremental             ->  1 Warning(s)      16 s against 3 s in isolation
```

**MSBuild skips up-to-date projects, so the compiler never re-runs and never re-emits their
warnings.** My original objection was about `--no-build` on the *suites*; this is worse and closer to
home — **the gate's own build is incremental.** Anyone who builds in an IDE before running the gate
makes that build a no-op, and the gate prints a clean bill over code that is not clean.

So the choice was never *grep versus `-warnaserror`*: **both sit downstream of a build that may
compile nothing.** `--no-incremental` is what makes any of them meaningful, and it is documented in
the script as load-bearing rather than as a performance setting, so nobody removes it to save 13
seconds.

**Cost inside a real gate: 81 s against 72 s.** Less than the isolated 16-vs-3 suggests, because the
gate's build was never fully warm anyway.

**After:**

```
!!! WARNINGS (Debug): 1 -- DEC-L-008 condition 1 is zero. This gate is RED.
  WarnProbe.cs(3,69): warning CS0219: The variable 'assignedButNeverUsed' is assigned but never used
Passed! 509 · 1032 · 326 · 724 · 46 · 56 · 59
[GATE RED -- ...]     exit 1
```

**The suites still ran.** A warning does not invalidate a test result, and stopping early would trade
one true report for another.

### Ancestry, not a hash, and that is the half that makes it usable

A hash says *different* and **conflates two states with opposite meanings**: a tree that is behind,
and a tree that is developing this file. Every task that has ever edited the gate looks like the
second — including this one. **A check that cries wolf at the developer is disabled long before it
catches the stale tree.**

```
this tree      HEAD contains the merged gate commit, file modified  -> "MODIFIED locally (not stale)"
SSAS_stale     HEAD does not contain it                             -> "STALE -- 1 commit behind"
chain-test     HEAD does not contain it                             -> would report 6 commits behind
```

### Why it warns where the lock refuses

**Fail-closed requires a signal you can trust, and this one is self-admittedly stale.** The lock's
evidence is authoritative — `sys.dm_tran_locks` *is* the truth — and proceeding wrongly destroys a
69-minute run. Here the evidence is a remote-tracking ref only as good as the last fetch, and the
failure is a **wrong green**, which a warning surfaces. Refusing on a stale ref would block every run
on the box: note 7x's own strand-the-instance failure, relocated.

### And why it does not fetch

```
git fetch origin ClaudeBranch     1338 ms
clean offline (DNS fails)          140 ms
HALF-OPEN NETWORK               22 201 ms      <- thirty per cent of a 72-second gate
```

**The failure that matters is not "offline", it is "offline slowly"** — the flaky-VPN case people
actually hit. Plus a credential prompt would hang a gate forever with no output. `DEC-L-051` bought
back 68 minutes; spending 22 seconds a run policing it would be self-defeating. **The weakness is
stated in the message rather than left for the reader to remember.**

**No suppression flag**, as ruled. If it becomes noisy the fix is a sharper check.

## Proposed `CODER.md` wording — the architect commits it

> 0. **The build succeeds — ENFORCED.** A failing build skips that configuration's suites and goes RED.
>    Until 2026-08-27 it did neither: the exit status was discarded and the suites ran `--no-build`
>    against the previous build's assemblies, so a run whose build failed with `1 Error(s)` reported
>    2752 passing tests and `[GATE GREEN]`.
>
> 1. **Zero warnings — ENFORCED.** The gate builds `--no-incremental` and goes RED on any warning.
>    `--no-incremental` is not a performance setting: MSBuild skips up-to-date projects, so a gate run
>    after an IDE build would otherwise report clean over code that is not.
>
> 3. **`Integration.Tests` when the task touched persistence — CONVENTION, NOT ENFORCED.** The gate
>    cannot evaluate this and you can. Nothing will stop you merging without it.
>
> 4. **The tests the task required exist in this diff — CONVENTION, NOT ENFORCED.** The gate prints the
>    counts. **It does not compare them to anything.**

And for the `DEC-L-053` worktree paragraph:

> **ONE GATE AT A TIME — ENFORCED** (exit 7, names the holder, reclaims only when its process is
> provably dead). **STALENESS — WARNED, NOT ENFORCED**: the gate says when this tree is behind on
> `scripts/gate.sh`, at the start and again at the verdict, naming the distance and your last fetch.
> It does not fetch and never refuses; offline is a normal condition. **Still yours:** do not edit the
