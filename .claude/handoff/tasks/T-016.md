# T-016 — `gate.sh`: the abort path must fail, and the default mode must fit this box

- **Branch:** `agent/T-016-gate-exit-code` — branch from `main`
- **Module:** Tooling
- **Issued:** pending T-014 close
- **Depends on:** T-014 — **do not start while a gate run is live.** The script's own header warns that
  bash reads the file incrementally, and a run on 2026-08-24 died on its own trailing lines after every
  leg had gone green.

## Goal

`DEC-L-007` made a green gate the merge authority for code. This gate reports green for a run that
never happened.

A precondition failure prints `!!! ABORT (Debug): PRECONDITION FAILURE` and **returns exit code 0**.
A background runner reports "completed (exit code 0)". Anything reading `$?` — CI, a wrapper, a future
agent — takes an aborted gate for a passed one. The script's own header states the principle it
violates: *"a gate that reports success on a failing run is worse than one that reports nothing,
because nobody goes looking."*

Second, smaller, same reading: the script defaults to `GATE_MODE=FULL` with a 4096 MB floor, while its
own line 56 documents **this** machine as LEAN — "because it hosts resident agent sessions alongside
the suite" — and FULL as "for a build box". The documented-correct invocation is the one nobody types,
and getting it wrong produces an abort that, per the above, reports success.

## Acceptance criteria

- [ ] **Every abort path exits non-zero.** Not only the memory precondition — audit all of them
      (the `testhost` running check, the protected-catalog check, the memory floor, and any other
      `!!! ABORT`) and confirm each returns a distinct, documented non-zero code. Some already do;
      the deliverable is that **none** returns 0.
- [ ] **A successful run still exits 0, and a failing suite still exits non-zero as it does today.**
      The existing meanings do not change. This closes a hole; it does not renumber the codes.
- [ ] **Proved by running it, not by reading it.** Force a precondition failure — the simplest is a
      floor the box cannot meet, e.g. `GATE_MODE=FULL` while under 4096 MB — and paste the abort output
      **with `echo "exit: $?"` immediately after**. Show it non-zero. That is the whole point of the task.
- [ ] **The default mode fits this box.** Either default to LEAN, or refuse to run without an explicit
      mode. Choose, and say why in the commit message. Line 56 is the authority; the code contradicts it.
- [ ] The header gains a line recording **why** the abort path must fail, so the next person editing
      it does not helpfully "clean up" an exit code back to 0.
- [ ] **The documented Integration timing is corrected while the file is open.** The header states
      45–55 minutes per Integration leg. Measured on this box under LEAN on 2026-08-25:
      **32 m 21 s Debug and 32 m 35 s Release** — within fourteen seconds of each other, total run
      69 minutes. Record the measured LEAN figure beside the FULL range and say which is which. The
      current text caused a 90–110 minute estimate that had to be revised down mid-run.
- [ ] **The memory note is corrected too, and this one matters more than it looks.** A healthy LEAN
      Integration leg on this box runs down to **~1,200–1,500 MB free mid-leg** — measured minima
      1,510 MB Debug and 1,232 MB Release, with peak `testhost` at 586 MB and 641 MB. Both legs cleared
      the 2,048 MB floor at start (3,550 and 2,985) and neither starved. Record it, because the floor is
      a **pre-leg precondition, not a running minimum**, and someone reading a mid-leg dip as an
      emergency would either tighten the floor wrongly or abort a healthy run.

## Design constraints

- **Do not restructure the script.** Its preconditions, memory floor, catalog reaping and protected-name
  refusal are carefully built and were paid for in real failures — the header records the dates. This
  is a correctness fix to the exit path and a default, not a rewrite.
- **Do not weaken a precondition to make a run easier.** If the floor is wrong, that is a separate
  argument with evidence; it is not this task.
- **The script must not edit, delete, or create anything outside `TestResults/` and the `SSAS_%`
  catalogs it already reaps.** Unchanged.

## Tests required

There is no suite for a shell script here, and inventing one is out of scope. **The evidence is the
criterion-3 demonstration**: a forced abort, its output, and `exit: <non-zero>` beneath it. Paste it.

`DEC-L-002` applies to the .NET gate — no file under `src/` or `tests/` is in scope, so the four-suite
gate is not run for this task. Do not run `gate.sh` against itself as a verification; run it only far
enough to trigger and show the abort.
