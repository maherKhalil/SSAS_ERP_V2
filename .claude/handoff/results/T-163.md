**Eight of thirteen documents name a fully-qualified permission on the row itself.** The other five either

`Platform.Localization.View`.

## ⚠ AND IT WOULD HAVE CAUGHT T-099, WHICH IS THE DECISIVE EVIDENCE

T-099 found `/leave-requests/{id}/approve` gated on `ViewLeave` where `ApproveLeave` belonged — a route
present, correctly named, satisfying every surface comparison, and handing approval to any reader.

**FP-013 names the right permission for that route and always did:**

```
document   POST /api/attendance/leave-requests/{id}/approve    Attendance.Leave.Approve
code       .RequirePermission(AttendancePermissionNames.ApproveLeave)
           ApproveLeave = "Attendance.Leave.Approve"                    <- agrees TODAY, after T-099
```

**The document was right while the code was wrong.** A document-versus-code permission comparison would have
failed on the day the defect was written. **The route inventories could not: they compare the code to
itself.**

## What I recommend, and the one thing that limits it

**Extend `ApiContractRowGuardTests` with a second assertion over the 124 rows that carry a fully-qualified
permission.** It is the same extractor, one more capture group, and the same live route table — which
already exposes the policy via `PlatformRouteInventory.AuthorizationOf`.

⚠ **Scoped to fully-qualified names only, deliberately.** Resolving FP-004's `View` to
`Platform.Localization.View` needs a per-document prefix that is nowhere written down; **inferring it would
put a guess inside a guard**, and a guard that guesses is worse than one that covers 65% and says so.
The uncovered rows should be listed by the test, not silently skipped.

# ITEM 12 — THE TWO GL CODES. **THEY ARE NOT THE SAME ANIMAL.**

```
Gl.JournalNumberConflict   declared, mapped to 409, NEVER RETURNED   -> MISSING RETURN. Wire it.
Gl.JournalImmutable        declared, mapped to 409, NEVER RETURNED   -> SURPLUS. No route can reach it.
```

## `Gl.JournalNumberConflict` — the condition is real and the answer today is 500

**Every link in the chain exists except the one that connects them:**

```
NextJournalNumberAsync            a READ-THEN-WRITE — three callers, incl. GlJournalPoster
UX_GlJournalEntries_Tenant_Company_Year_Number   unique index, so the race IS caught
TenantUnitOfWork                  SqlException 2601/2627 -> IdentityAccessErrors.UniqueConstraintViolation
                                  ("Persistence.UniqueConstraint")
GlApiErrorMapper                  has NO arm for "Persistence.UniqueConstraint"
                                  -> falls to the default -> WriteFailure -> 500
JournalErrors.NumberConflict      declared, mapped to 409, returned by nothing
```

**So two concurrent postings into the same fiscal year produce a 500 with no exception and no log entry**,
while the 409 written for exactly that case sits unused. **This is the `T-125` shape, not the `T-095`
shape**: not a dead arm, a disconnected one.

**Recommendation: return `JournalErrors.NumberConflict` when the save fails with
`Persistence.UniqueConstraint`**, matching `CreateTenantCommandHandler`, which already does precisely this
(`saveResult.Error == IdentityAccessErrors.UniqueConstraintViolation ? TenantLifecycleErrors.CodeExists`).
**The precedent is in the codebase and this is the same three lines.**

## `Gl.JournalImmutable` — surplus, and its own comment argues for a path that does not exist

Its declaration carries a stated reason:

> *"Kept for the API surface even though the write boundary is what actually enforces it: a caller who
> attempts a mutation deserves a named refusal rather than an infrastructure exception surfacing raw."*

**But GL exposes no mutation on a posted journal at all** — the live routes are `GET /journals`,
`GET /journals/{id}` and the journal-draft family. **There is no `PUT` and no `DELETE` for a caller to
attempt**, so the "infrastructure exception surfacing raw" it defends against cannot occur.

**Recommendation: remove the declaration and the mapper arm, OR keep both and correct the comment to say no
route can produce it.** I lean to **removing**: `T-095` ruled a dead arm worse than an honest gap, and the
absent verbs are already `OD-ATT-0012`-style decisions made visible in the surface. **But the note is a
deliberate act by GL's author and reversing it is a judgement, not a correction — so I am recommending,
not doing.**

**The grep filtered lines by `static readonly|= new`, and these declarations put the code string on its own

Third time today the false result came from the pattern rather than the material —
`class (…|EntitlementGrant)` missing `TenantEntitlementGrant`, a `sed` exclusion chain that leaked, and
