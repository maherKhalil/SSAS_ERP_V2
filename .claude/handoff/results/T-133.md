## The cause, measured

```
entity types in the model the guard inspected:   tenant = 2      platform = 36
GL / HR / Payroll / Attendance entities in it:   NONE
```

**`TenantModel()` built `new TenantDbContext(options, …)` directly.** Every module's tables arrive through an
`ITenantModelContributor` registered in DI — **so a directly-constructed context has two entities, and
`Every_persisted_string_in_the_tenant_model_is_unicode` was asserting over two.**

**The test's name says "the tenant model". It had the core of it and none of the ERP.**

**The Platform half was always real** — `PlatformDbContext` configures its own 36 entities, which is why the
acknowledged list is populated and accurate. **The guard was half a guard and read as a whole one.**

# THE FIX, AND IT IS ONE ARGUMENT

`TenantDbContext` already accepts `modelContributors`, and `DepartmentArchitectureTests:305` already used it.
**The pattern existed; this guard did not use it.**

```csharp
modelContributors:
[
  new HrTenantModelContributor(), new GlTenantModelContributor(),
  new PayrollTenantModelContributor(), new AttendanceTenantModelContributor()
]
```
