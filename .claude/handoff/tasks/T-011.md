# T-011 — `ADR-017`, `ADR-026`, `ADR-027` move to `Accepted`

- **Branch:** `agent/T-011-adr-status` — branch from `main`, after T-010 merges
- **Module:** Docs / architecture governance
- **Issued:** 2026-08-25
- **Depends on:** T-010 — which sharpened this from tidying to correctness

## Goal

`DEC-L-011` ruled these three `Accepted`: the front-matter is stale bookkeeping, not a signal that
the rulings are provisional. Five approved packages treat them as binding and four modules inherit
`ADR-027`'s `decimal(19,4)`.

T-010 made it worse in a way that is hard to ignore: **`ADR-029` is `Accepted` and `depends_on`
`ADR-017`, `ADR-026` and `ADR-027` — all three still `Proposed`.** An accepted decision resting on
three proposals is not a cosmetic inconsistency.

**This does not reopen their content.** It records an acceptance that happened and was never written back.

## Acceptance criteria

- [ ] `ADR-017`, `ADR-026` and `ADR-027` each carry `status: Accepted` with a date, in the same
      front-matter shape the other Accepted ADRs use — `ADR-015` and now `ADR-029` are the references.
- [ ] **Each gains a short line naming what evidences the acceptance** — the packages that closed
      owner decisions citing it, and the shipped code that inherits it. Not a rewrite of the ADR: one
      line, so a reader can see *why* it is Accepted rather than taking it on assertion.
- [ ] **Nothing else in the three files changes.** No re-wording of a decision, no updated consequence,
      no "while we're here". `git diff` should be front-matter plus one line each.
- [ ] `docs/14-Engineering/ADR/README.md` reflects the three statuses if it carries them.
- [ ] `git diff main...agent/T-011-adr-status --stat` shows **at most four files**, all under
      `docs/14-Engineering/ADR/`.

## Design constraints

- **The evidence line must be checkable.** Name a package, a PR, a file — the standard T-001 set. "It
  is widely used" is not evidence; "`FP-008` closed `OD-POS-004` citing it, and `SalaryGradeConfiguration`
  applies it" is.
- **Do not backdate.** The `date:` is today, when the record was corrected. If the front-matter carries
  a separate original date, leave it.
- If the evidence for one of the three turns out to be thinner than `DEC-L-011` assumed, **say so and
  stop on that file**. Two accepted and one queried is a better result than three accepted and one wrong.
