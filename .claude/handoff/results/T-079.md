# 1. IS THE PATH STATICALLY TRACTABLE? **NO.**

Four reasons, each measured rather than judged:

**a. There is no semantic analysis available at all.** `Microsoft.CodeAnalysis` is referenced by **no**
test project and is absent from `Directory.Packages.props`. Without Roslyn there is no call graph to
walk — the question is not hard, it is unavailable.

**b. The reachable set spans layers.** `ChangeEmployeePositionCommandHandler` returns eight errors itself
**and** calls `employee.ChangePosition(...)`, which returns `PositionRequired` and `PositionUnchanged`
from `Employee.cs:571,579`. A site's set is a transitive closure, not one file.

**c. It crosses interfaces.** Handlers depend on `IEmployeeRepository`, `IEmployeeImportRunRepository`.
Which concrete type answers is a **composition fact**, not a static one.

**d. It crosses modules — legitimately.** `PayrollApiErrorMapper` maps `Company.*`; `GlApiErrorMapper`
maps `Company.*` and `Persistence.*`. **A site's candidate set is not bounded by its own module's
assemblies**, so even the population to check over cannot be derived.

# 2. THE ACHIEVABLE VERSION — declared per-site responsibility, and the tree agreed

Your expectation held. Responsibility is **declared by code family**, not derived: a wrong derivation
accuses innocents, and a declaration is reviewable. The families partition cleanly onto seven sites:

```
Attendance(69)  Gl(28)  Payroll(45)
Employee(33)  Position(30)  Department(25)  EmployeeImport(10)  EmployeeImportRun(4)  EmployeeExportRun(1)
```

**A site may map codes outside its families without penalty** — the import site maps three
`Employee.Position*` because an import surfaces employee errors. Only the **responsible** families are
asserted; anything extra is a site being helpful.

**And a second fact closes the model's own escape hatch.**
`Every_declared_error_family_is_owned_by_exactly_one_site` fails if a family is claimed by nobody.
Without it, an error in a new family would be covered by no site, examined by nothing, and **every
per-site assertion would stay green** — the same shape as a route outside an inventory.

## **AND I NEARLY EXCULPATED FOUR OF THEM FALSELY**

I searched for `EmployeeImportRun.Create` to see whether the aggregate was ever constructed, got **zero
call sites anywhere in `src/` or `tests/`**, and was one step from reporting four errors as *unreachable
by construction*.

**There is no `Create`.** The factories are `Validated`, `Applied` and `Refused`
(`EmployeeImportRun.cs:125,141,160`), and `ImportEmployeesCommandHandler.cs:168,572` calls two of them.
**I had guessed a name and read its absence as evidence.**

You warned about over-reporting. **This would have been the same error inverted** — a false
*exculpation*, which is worse, because a missing accusation leaves a live 500 in place and produces no
red to notice it by. **An absence is only evidence when you know the name you searched for is the right
one.** I have made this exact mistake twice before on this board; this is the first time it was caught
before reporting rather than after.
