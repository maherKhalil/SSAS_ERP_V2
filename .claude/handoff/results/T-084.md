# THE GUARD I ASKED FOR AND DID NOT GET — REPORTED HONESTLY

**You asked whether a construction exists where the handler cannot silently skip the resolution. I did not
find one, and I want to be precise about what is achieved instead.**

**What is achieved:** the parameter has **no default**, so every call site must say something. Omission is
a compile error; skipping is a written `null`.

**What is not:** the aggregate still cannot distinguish *the user was unresolvable* from *the caller passed
null on purpose*. **Both are correct behaviour from its side**, and no signature fixes that — the aggregate
would have to reach out and resolve, which inverts the dependency and is worse.

**A wrapper type** — `ActingEmployee.Resolved(id)` / `ActingEmployee.Unresolved()` — would make the skip a
named act rather than a bare `null`. **I did not take it**, because it makes the mistake *louder* rather
than *unrepresentable*, and it adds a type to a domain surface to improve a comment. `ModulePermissionDefinition`'s
missing `Scope` property is genuinely unrepresentable; this would only be conspicuous. **Tell me if you
want it anyway — it is a small change and the argument is close.**

**So the assertion carries the weight**, exactly as you required:

```
The_handler_resolves_the_acting_user_before_deciding_at_root
  Assert.Equal([ActingTenantUserId], world.Resolver.Asked)
```

**A handler that never called the resolver passes every other test in the file** — the aggregate receives
`null`, reads it as unresolvable, and approves. **This one asserts the question was asked, and asked about
the acting user rather than somebody else.**
