# T-074 — A disposition clears the marker class it names, and nothing else

**This was specified in chat this morning as "item 64" and never written to a file. That is my fault
and `PROTOCOL.md` #7 names it: *files, not chat, carry the detail*. The spec below is complete;
nothing needs recovering from the conversation.**

## The defect this guards

`FP-011/requirements.md` carried a legend clearing its `OWNER-DECISION-REQUIRED` markers. The same
file carried **fourteen live `| **Open** |` table rows** — a second marker class the legend never
mentioned and therefore never cleared. Eleven named a decision the package had already ruled and
recorded in its own `README.md`. One reasoned from an option that lost.

**Nothing detected it.** The corpus sweep could not see the rows at all: its marker list held
`**OPEN**` and the file writes `**Open**` — a one-character difference.

## What to build

An arch test, beside `CriterionCommentGuardTests`, asserting:

> **No `docs/17-features/` file may carry a live `| **Open** |` row citing a decision id that the
> same package's own documents record as ruled.**

`[Trait("Tripwire", …)]` — **never `Criterion`**.

## Four requirements, each with the reason it exists

**1 — THE QUOTING RULE IS ASYMMETRIC.** In this corpus a **violation** is a plain table row and a
**disposition** is a `>`-quoted block. So **violations must skip `>` lines; dispositions must READ
them.** A symmetric exclusion is blind to every disposition in the repository and reddens every
correctly remediated file. *A dry run got the right answer only because its id-collection loop
happened to omit the filter — applied as originally specified it would have reported a verified fix
as ineffective.*

**2 — "NAMED" MEANS STRUCTURALLY NAMED, NOT MENTIONED.** A predicate treating *"the id appears
anywhere outside an open cell"* as dispositioned greens a stale row because the decision is merely
**discussed** elsewhere in the file. Require the structure — **a row pairing an id with a verdict**,
the shape `| **`OD-XX-NNNN`** | <ruling> | **stale** |`. Prose must green nothing.

**3 — LITERAL IDS ONLY, NEVER RANGE EXPANSION.** `OD-GL-0001 … OD-GL-0009` names **two** ids and
implies nine. Assert this with a fixture so nobody later "improves" it into a range parser.

**4 — A ROW IS RED IF *ANY* ID ON IT IS UNNAMED.** A multi-id row is exactly where a
partially-complete disposition hides.

## The boundary assertion — this replaces an allow-list

An earlier version of this spec exempted the files carrying **cell-scoped dispositions** (a
correction written inline in the corrected cell, with no delimiter at all — `"⚠ CORRECTED — THIS
CELL SAID …"`). **That exemption was vacuous:** measured, **none of those six files contains a single
`| **Open** |` row**, so it would have exempted files the check cannot score anyway.

Assert this instead:

> **No file containing a `| **Open** |` row may also contain a cell-scoped disposition.**

True today, so it ships green honestly. It reddens **exactly** when the two forms collide, which is
the only moment the intra-cell blindness could produce a wrong verdict.

⚠ **Its detector is the `THIS SAID` / `~~` vocabulary, which is known-incomplete** — a fourth
phrasing (`"THIS CELL SAID"`) was already found once. **The failure direction is safe:** an undetected
cell-disposition means the file is *not* excluded, so the main guard scores it and the preserved
original trips a red. A false positive that surfaces, not a false negative that hides.

## The failure message must carry both readings

**Never a single instruction.** A reader given one instruction for two situations will delete the
preserved original.

> *"Either this row is stale — name the id in a disposition table — or it was corrected in place;
> move the correction to a quoted block, or add the id."*

**It must say *name the id*, never *remove the row*.** The house convention preserves originals; a
message naming only the destructive path will get the destructive path taken.

## Anti-vacuity (was "item 65" — same file, run it with this)

Full four-state plant, **run state 1 first**:

1. plant a stale `| **Open** |` row citing a ruled id, no fix → **RED**
2. plant + fix → GREEN
3. no plant + fix → GREEN
4. ⚠ **REACH, where a GREEN is the finding:** plant the row inside a `>`-quoted block, and again in a
   prose-preserved file (`FP-012/requirements.md` retires its whole body with one italic sentence at
   `:7`, no quoting). **Both must stay GREEN.** If either reddens, the exclusions punish honest
   corrections.

**Stage before planting.** Never `git checkout -- tests/` — it blanket-reverts your own lane and has
destroyed uncommitted work here before.
