# T-070 — Make the gate say what tree it measured

**`DEC-L-065` as a procedure is a rule someone forgets. This is the structural half.**

## What happened

The coder's branch was at `65dcff3`, where FP-015 was a skeleton. Its gate run reported **eight
`REQ-SS` failures** — from the architect's **uncommitted working-tree files** in the shared tree.

**The red was correct and the attribution was not.** A merge-authorising verdict measured work that
was not on the branch being merged, and nothing in the output said so.

**Six index repairs today were the same shared tree. This is the first time it changed a verdict.**

## What to build

**The gate reports the state of the tree it is measuring**, at the start and again at the verdict:

- Modified tracked files, and untracked files, **counted and named** — not "the tree is dirty".
- **Whether `HEAD` matches the integration branch**, and by how far.

**Restate at the verdict, not only at the start.** A line printed at second 3 of a 4095-second `PHASE`
run is not a line anyone reads — the argument that won `[GATE RED -- <scope>]` and it applies
unchanged.

**Report; do not fail.** A dirty tree is the normal state of a window mid-task, and a gate that
refused one would be refused by its user within a day. **The defect was never the dirty tree — it was
a verdict that did not say what it measured.**

## What it must NOT do

- **Do not try to decide whose files they are.** Two windows, one tree, and no reliable attribution
  exists. **Name the files and let the reader conclude.** A guard that asserts a cause it cannot know
  is the defect this repository has now recorded eight times.
- **Do not exclude `.claude/`.** The FP-015 case was documentation, and excluding it would have made
  this exact incident invisible.

## Also — two stale references to a retired variable

`DEC-L-056a` retires `MSYS_NO_PATHCONV` outright: **do not set it, anywhere, exported or prefixed.**
Verified with it unset — `commit-tree`, `ls-tree` and `gh` all work, and `DEC-L-054b` removed its last
use case.

Two places still describe it as something to scope rather than something retired:

```
scripts/gate.sh:1096   "MSYS_NO_PATHCONV=1 in the launching shell breaks powershell.exe -File"
scripts/trace-check.py:1415   restricts: MSYS_NO_PATHCONV
```

**Correct the first to say the variable is retired**, keeping the sampler consequence — that text is
the only reason anyone will understand a dead sampler. **The second is a mechanism declaration and
should stay**; a `restricts:` entry for a retired variable is exactly what `DEC-L-057`'s join is for.

## Done when

- A run in a tree with uncommitted or untracked files says so, **at the start and at the verdict**,
  naming them.
- A run in a clean tree at the integration branch says **that**, rather than saying nothing —
  absence must not read as not-applicable.
- **Demonstrated by planting both cases**, per `DEC-L-059a`, and **prove the clean case can fail**:
  a report that only ever prints "clean" is the check that cannot fail, one task after you found one.
- `GATE_SCOPE=TASK` green, counts on baseline.
- Non-gated by the letter — `scripts/` only. Push and wait for `MERGE T-070`.
