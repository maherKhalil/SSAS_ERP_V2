## Acceptance criteria

- [ ] `acceptance-criteria.md` gives every one of the 28 `REQ-SUB` at least one `AC-SUB`, contiguous
      from `0001`. Criteria are observable — a named behaviour, a refused request, a value that must
      hold — never "correctly implemented".
- [ ] `test-scenarios.md` gives every `AC-SUB` at least one `TS-SUB`, contiguous from `0001`, each
      naming the suite it belongs in. `Integration.Tests` for anything crossing to real SQL,
      `Architecture.Tests` for the guards below, unit suites for invariants.
- [ ] `traceability-matrix.md` chains `REQ-SUB → AC-SUB → TS-SUB` in a pipe table whose **first cell
      carries the `REQ-` identifier**, because that is what `trace-check` parses. Counts derived by
      running the script, not typed.
- [ ] **Three obligations are carried into the criteria, not left in prose** — they are the things
      most likely to be dropped between this package and an implementation prompt:
      1. `PlatformDbContext` has no `PreventAppendOnlyMutation`; the append-only ruling needs it
         before any FP-014 entity carries `IAppendOnlyEntity`.
      2. An architecture guard asserting every `Platform.Plans.*`, `Platform.Subscriptions.*`,
         `Platform.EntitlementGrants.*` and `Platform.Invoices.*` name is used **only** with
         `RequirePlatformPermission` — your T-007 mitigation for the prefix ambiguity.
      3. No backfill and no default plan, and the migration must not ship in the same release as the
         enablement gate.
- [ ] `py scripts/trace-check.py FP-014-subscription` **runs GREEN on the package** — zero failures,
      all spaces contiguous, coverage rules 3 and 4 satisfied. Run it with every other package present
      so cross-package citations resolve; isolating FP-014 manufactures warnings that are not real.
      `BUILD BLOCKED` on 17 unruled decisions is expected and correct — the ratification file is not
      yours to write.

## Design constraints

- **No en-dash ranges.** `AC-SUB-0006`–`0008` reads as three identifiers to a human and one to a
  string search; `trace-check`'s RANGE check exists because ten identifiers hid behind them in FP-012.
  Enumerate.
- **A test scenario states what would fail if the behaviour were absent.** `TS` rows that restate the
  requirement prove nothing — the same standard the coder charter applies to real tests.
- **Two seat-cap scenarios cannot be written yet.** `OD-SUB-0017` ruled seats-plus-limits but not the
  consequence of exceeding a cap, and no grace period. Where a criterion depends on it, mark it a
  declared gap naming the open ruling rather than choosing a behaviour. I have put it to the owner.
