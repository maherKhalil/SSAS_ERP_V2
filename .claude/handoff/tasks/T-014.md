# T-014 — `PlatformDbContext` gains the append-only guard

- **Branch:** `agent/T-014-platform-append-only` — **branch from `main`**, after FP-014 has merged
- **Module:** Platform
- **Issued:** 2026-08-25
- **Depends on:** the FP-014 whole-package merge

## Goal

**This is the first task in this loop that writes C#, and the first where `DEC-L-008` decides whether
it merges.** Read `.claude/roles/CODER.md` § Merging in full before you start.

`OD-SUB-0008` ruled append-only history for records that `ADR-017` places in the **Platform** database.
`PreventAppendOnlyMutation` exists only on `TenantDbContext` — defined at `:484`, called from that
context's `SaveChangesAsync` at `:158`. `PlatformDbContext.SaveChangesAsync:107` calls nothing
equivalent, and all fourteen references to the guard are tenant-DB modules. An FP-014 entity carrying
`IAppendOnlyEntity` in the Platform database today would have the appearance of immutability and none
of the enforcement.

`TS-SUB-0033` is the executable form of this obligation and is **red on arrival by design**. Under
`DEC-L-008` no FP-014 build task can honestly report a green gate until this lands, which is why it
comes first.

## Acceptance criteria

- [ ] `PlatformDbContext.SaveChangesAsync` refuses `EntityState.Modified` and `EntityState.Deleted`
      for any `IAppendOnlyEntity`, with the same failure mode and the same message as
      `TenantDbContext` — one behaviour, not two dialects of one.
- [ ] **A test that fails without the guard and passes with it.** This is the criterion that matters:
      a test which passes either way proves nothing and is not coverage. Prove it — remove the guard,
      watch the test fail, restore it, and say so in the result.
- [ ] An `Architecture.Tests` guard asserting **both** contexts enforce append-only, so the next
      context added to this repository cannot quietly omit it. The existing asymmetry survived four
      modules precisely because nothing asserted the symmetry.
- [ ] The gate is green under `DEC-L-008` — all four conditions — and **`Integration.Tests` runs**,
      because this touches persistence. Through `scripts/gate.sh`. Counts reported against the board
      baseline: build 0 warnings, Architecture 462, Platform 963, HR 326, API 685, Payroll 56,
      Attendance 59, Finance 46.
- [ ] Merged on green per `DEC-L-007`, via `gh pr create` then `gh pr merge --merge --delete-branch`.

## Out of scope

- `TenantDbContext`. It already does this correctly. Do not refactor the two into a shared base to
  "remove duplication" — that is a larger design change than this task, it touches a context four
  modules depend on, and eleven duplicated lines are not the problem being solved.
- **Adding any `IAppendOnlyEntity` to the Platform model.** No Platform entity implements it today and
  none should be added here — FP-014's entities arrive with FP-014.
- Every FP-014 document. The package is merged and closed.

## Design constraints

- **Mirror the existing guard.** Same shape, same exception type, same message. A reader who knows one
  context must not have to re-learn the other.
- **Match the call ordering convention.** `TenantDbContext` calls its guards at the top of
  `SaveChangesAsync`, before anything touches the database. Read `:155`–`:162` and follow it.
- **If the behavioural test cannot be written without adding a production entity**, say so as a
  `NEEDS-DECISION` with the options rather than inventing one. A test-only entity registered in a
  test-only model is legitimate; a production marker added to make a test compile is not.
- Zero warnings. The build is at zero today and a warning you introduce is a failure.

## Tests required

- `Architecture.Tests` — the symmetry guard across both contexts.
