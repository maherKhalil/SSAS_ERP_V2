# T-018 — `TenantDbContext` passes the surface assertion by accident; make it deliberate

- **Branch:** `agent/T-018-tenant-context-surface` — branch from `main`
- **Module:** Platform
- **Issued:** 2026-08-25
- **Depends on:** T-003 merge

## Goal

You raised this in T-015 and it is the last loose end from that fence.

`AppendOnlyEnforcementArchitectureTests` asserts that no persistence context declares a convenience
overload — `SaveChangesAsync(CancellationToken)` or `SaveChanges()` — because a context that declares
neither has nowhere to put a bypassable rule. `PlatformDbContext` satisfies it **by design** after
T-015. `TenantDbContext` satisfies it **by accident**: it happens not to declare them, nothing records
that as a requirement, and a future edit adding one would break a rule nobody knows applies to it.

The guard is green today for both. The difference is that only one of them knows why.

## Acceptance criteria

- [ ] `TenantDbContext` carries a comment at its `SaveChanges`/`SaveChangesAsync` surface recording
      **why no convenience overload may be declared here** — the same reasoning `PlatformDbContext`
      now carries. A future editor adding one must be stopped by the file, not only by a test they may
      not connect to the change.
- [ ] The comment names the mechanism, not just the rule: EF Core routes `SaveChangesAsync(ct)` →
      `SaveChangesAsync(bool, ct)` and `SaveChanges()` → `SaveChanges(bool)` by virtual dispatch, so a
      rule hung on an outer overload is reachable past.
- [ ] **The architecture guard is confirmed to actually cover `TenantDbContext`** — not assumed. Show
      it: name the contexts the assertion enumerates, and demonstrate the test fails if a convenience
      overload is added to `TenantDbContext`. `DEC-L-016` — a guard that passes both ways asserts nothing.
- [ ] Gate green under `DEC-L-008`. **`Integration.Tests` runs** — this touches a persistence context
      four modules depend on, even if the change is comment-only in production code. Counts against the
      board baseline: Architecture 466, Platform 977, HR 326, API 685, Payroll 56, Attendance 59,
      Finance 46, Integration 782 both configurations.
- [ ] Merged on green per `DEC-L-007`.
