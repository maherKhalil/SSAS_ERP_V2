**Item 19 was commissioned to find unbacked read-then-writes. There are none.** All 61 unique indexes are
in place and every guard site has one that applies.

**What is missing is not the constraint. It is the ANSWER.**

```

guard + two reachable indexes, deliberately unnamed  1 site   GL journal reversal (T-165, ruled)

**Three module mappers carry ZERO `Persistence.UniqueConstraint` arms** — `AttendanceApiErrorMapper`,
`GlApiErrorMapper`, `PayrollApiErrorMapper` — and only two handlers in those modules translate, **both of
them built this week** (T-165 posting, T-171 entitlement).

```

**Each is T-165's defect exactly**: a check that two callers can both pass, a unique index that decides it
at commit, and a loser who receives `Persistence.UniqueConstraint` with no arm to map it — so the default
answers 500 for what is a plain business conflict. **Every one of them already has a `*CodeConflict` or
equivalent error declared and mapped to 409.** The codes exist; nothing returns them on the race.

⚠ **All seven are RETRYABLE**, and all seven are the same shape as the entitlement race rather than the
reversal: **the losing caller learns the name is taken and can choose another.** None is terminal.

# THE ALIGNMENT AXIS YOU ASKED FOR — AND ONE MODEL CASE WORTH COPYING

**Does the index key match the read's predicate?**

```
6 of 7        match exactly
LeaveBalance  NARROWER than the read — index omits CompanyId (recorded, T-174)
PayrollRun    guard predicate `ReversedUtc == null` == index filter `[ReversedUtc] IS NULL`   <- MODEL
```

**`ExistsForPeriodAsync` is the case to copy.** Its predicate and the index's filter state the same rule in
two languages, and `PayrollRunCommandHandlers.cs:713` records why: before T-112 the guard *"matched any run
in any state"* while the rule intended only unreversed ones, **so the rerun half of reverse-and-rerun was
refused by the database from the day the comment claiming it worked was written.**

**That is the failure mode "check the filter, not just the index" exists to catch, and it has already
happened once in this codebase.**

# ⚠ MY OWN SWEEP HAD TWO MORE INSTRUMENT FAILURES, BOTH THE SAME FAMILY

**One.** `grep "ExistsAsync"` missed `ExistsForFiscalPeriodAsync` and `ExistsForPeriodAsync` — they end in
`PeriodAsync`. **A suffix filter.** Caught by scanning the repository INTERFACES, which enumerate the
methods rather than matching their names.

**Two.** The leave-balance miss that started this: `grep "LeaveBalance" | grep -i hasindex` needs both words
on one line, and the lambda parameter is `balance`. **A co-location filter.**

**Both are the same shape as the four before them and none is `DEC-L-086`'s enumerate-versus-match** —
each *was* an enumeration, of the wrong thing. **The control that works for all six is reading the whole
declaring block**: the `Configure` method, the interface, the errors class. Grep locates it; it does not
adjudicate it.

## For the architect

- **Seven sites, all the same fix, all three lines each** — `saved.Error.Code ==
  PersistenceErrorCodes.UniqueConstraint` → the module's existing conflict error. **Handler-side per
  `DEC-DEP-0027`, because Attendance, GL and Payroll each have several unique indexes and a module-wide arm
  would misname them** — exactly the argument that kept T-165 out of `GlApiErrorMapper`.
- **Each needs its own reachability check before translating**, the way T-165 did: the handler must be able
  to hit exactly one index. I have NOT verified that per site — it is the first thing the build must do,
  and where it fails the site stays unnamed like the reversal.
- **Recommend one task per module** rather than one for all seven, so a wrong reachability judgement in one
  module cannot ride in on another's gate.
- **`DEC-L-069`:** 61 unique indexes enumerated with their filters; every guard site cross-checked against
  its index key AND the read's predicate; the three mappers' arm counts measured rather than inferred.
