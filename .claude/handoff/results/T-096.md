# THE ONE PLACE I WENT BEYOND THE RULING

**`department.not_found` had exactly the collision `position.not_found` had:** 400 in the import row mapper,
404 on the resource route, one wire string carrying two statuses.

**The ruling named only `position.not_found`.** Applying it to one of two identical instances is the
partial-collapse problem the architect raised in the same message — *"ruling two of nineteen is exactly
what I did to `Employee.Position*`"* — and the new guard would have gone red on the other the moment it
existed.

**Both split, under the file's own convention.** `StatusNotCreatable` already used
`employee_import.status_not_creatable`, so the prefix was not invented:

```
employee_import.position_not_found     400   the position NAMED IN THIS ROW is invalid
position.not_found                     404   the position RESOURCE does not exist
employee_import.department_not_found   400
department.not_found                   404
```

**And the two siblings that do NOT collide keep their strings.** `department.inactive` and
`position.inactive` are declared nowhere else, so they carry one status and one meaning. **Renaming them
would change a wire contract to fix a defect they do not have — the split follows the collision, not the
file.**

**`EmployeeErrorWireContractTests` and the import-report test both had to be edited**, which is exactly
what they exist for: *"a future change that turns `request.invalid` into `position.not_found` is a contract
change and has to be made deliberately here."*

# THE NEW GUARD, AND WHY THE OLD ONE COULD NOT SEE THIS

`The_same_code_answers_the_same_status_at_every_site_that_maps_it` compares which status each **error code**
receives. **It cannot see two sites mapping DIFFERENT constants that carry the SAME wire string** — which
is precisely what the two `*.not_found` pairs did.

**A caller sees strings. It has never seen a constant or an error code.**

So `A_wire_code_string_carries_one_status_across_the_whole_product` enumerates **every `ApiError`
declaration**, not only the ones an arm uses — a constant declared and unused still fixes a string to a
status, and the collision is real the moment something maps to it. That is what makes it catch the defect
*before* a route starts answering with it.

**Proved red before green** by replanting the old string:

```
position.not_found: 400 (EmployeeImportRowErrorMapper.PositionNotFound), 404 (PositionApiErrorMapper.PositionNotFound)
```

**The arm-level guard survives** — it catches a different mistake, the same *error* answered differently,
one step earlier.

## The other three, briefly

**`Company.ContextRequired` → 403.** Ruled on the distinction the product already draws:
`Company.SelectionRequired` is 400 because the caller must select one; this is an authorization context
that could not be established, which no change to the request can fix.

**`EmployeeImportRun.InvalidActor` → 500.** T-080 had already ruled 500 at the sibling site and given the
reason — reaching the aggregate's actor guard means the handler's own precondition passed and the aggregate
refused anyway, an internal inconsistency rather than a caller fault. One site was right and the other was
never brought into line.

**`Persistence.ConcurrencyConflict` → 409 on the auth routes.** Those routes carry no mapper by design;
each branches on the expected error and sends everything else to `503 service.unavailable`. A concurrent
write landed in that bucket. **503 tells a caller the service is down when the fix is to retry**, and points
an operator at an availability incident that is not happening. Implemented as ONE error-aware fallback
replacing five `503` call sites, so a future addition inherits it rather than repeating the mistake.
`Authentication.AccessTokenUnavailable` stays 503 — it genuinely is availability.
