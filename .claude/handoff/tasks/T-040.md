# T-040 — The real entitlement resolver, and expiry at the gate

- **Branch:** `agent/T-040-entitlement-resolver` — branch from `main`
- **Module:** Platform (commercial plane)
- **Issued:** 2026-08-26
- **Depends on:** T-039 merge (PR #82). **Gated.**

## Goal

The seam reads through `ITenantModuleEntitlement`; the schema holds plans, subscriptions and grants;
the transitional implementation grants everything. **This replaces it.**

It does not seed anything — a tenant with no subscription still reaches no gated module after this
task. The trial that stops that being a lockout is T-041, and **that ordering is deliberate**: the
resolver must be correct before anything depends on it being lenient.

## Acceptance criteria

- [ ] **The real resolver replaces the transitional one** — it is not added beside it. The architecture
      test asserting exactly one implementation must still pass, and the transitional type is **deleted**,
      not left unregistered.
- [ ] **Entitlement resolves as plan ∪ additive grants**, from the subscription in force, on
      `OD-SUB-0008`'s ordering — no closing column, latest append wins. A grant may raise a cap and
      never lower one (`DEC-L-009`).
- [ ] **Expiry denies gated modules and never denies authentication** (`DEC-L-033`). Prove both halves:
      an expired tenant is refused a gated route with **403**, and reaches a platform-plane route
      normally. `REQ-SUB-0013` already exempts the platform plane, so this should need no special case —
      **if it does, say so, because that would mean the exemption is not doing its job.**
- [ ] **THE CACHE MUST NOT OUTLIVE `TermEndUtc`, AND THIS IS THE HARD PART.** `OD-SUB-0004` ruled
      invalidation-on-change and never TTL. **Expiry is not a change — nothing is written when a term
      lapses.** So a cached entry holding only *enabled: true* is wrong from the instant of expiry and
      stays wrong until something unrelated evicts it. Carry the term in the cached value and evaluate
      it against the clock, or key the entry so it cannot survive the boundary. **Choose, say why, and
      test it: a test that advances a clock past `TermEndUtc` and asserts the gate refuses without any
      write having occurred.**
- [ ] **A plan edit changes every tenant on that plan.** Invalidation keyed only on `TenantId` misses
      them all — the fan-out flagged in T-006. Cover it or state plainly that it is uncovered and why.
- [ ] Gate green under `DEC-L-008`, **Integration runs against real SQL**, merged on green. Baseline:
      Architecture 474, Platform 1015, API 713, HR 326, Finance 46, Payroll 56, Attendance 59,
      **Integration 791 both configurations**.

## Out of scope

- **Seeding any subscription, plan or trial.** T-041. This task must leave a tenant with no
  subscription reaching no gated module, and **that is the correct interim state, not a regression.**
- The administration surface to create plans or assign subscriptions.
- Seat caps, metering, invoicing. `ADR-029` still forbids any field capable of holding cardholder data.
- The five test hosts' composition — T-034 settled it; they register the contract and will resolve
  whatever is registered.

## Design constraints

- **Resolution is per request, server-side, and never in the token** (`DEC-SUB-0005`, `REQ-SUB-0008`).
  `FP-002` excludes subscription information from claims under exact cardinality.
- **The subscription surface itself must stay reachable while the tenant's ERP database is
  unavailable** (`REQ-SUB-0005`, `ADR-017` § Platform database boundary). The resolver reads the
  Platform database only.
- **A cap in force is a property of the subscription record live at that moment.** Do not resolve a
  historical question against today's record.
- Match the established conventions; a novel shape is a defect even when it compiles.
