# T-061 — The traceability matrix: eight shapes, and widening the parser changes what "green" means

**Do not start the parser change until the measurement below is done and reported.** This task is
mostly measurement; the code is small and comes last.

## The premise, checked before writing this — `DEC-L-060`

```
packages with NO parseable chain rows        8 of 14
packages coverage rules 3 and 4 apply to     6 of 14
```

**Coverage rules 3 and 4 have never run on eight packages.** Widening the parser does not merely
report more — **it subjects eight packages to two rules they have never been held to.** A package can
go red without anything about it changing.

**That is the whole risk, and it is why this is not a parser fix.**

## Eight failing matrices, eight shapes — the coder's measurement in T-060

```
package    cols   first cell
FP-001        3   DEC-
FP-002        5   none
FP-003        7   none
FP-004        4   BR-
FP-005        7   none
FP-006        7   none
FP-008        3   REQ-     <- has the anchor, too few columns
FP-009        2   REQ-     <- has the anchor, too few columns
FP-014        4   REQ-     <- parses today
```

The parser encodes the modern four-cell `REQ-`-anchored chain. The legacy chain is anchored by
`DEC-` or `BR-`. **That does not explain FP-008 and FP-009**, which carry the anchor and are simply
narrower — so this is not one defect with one fix.

## And not every matrix should be parsed

**`FP-007` is GREEN today with a declared gap**: its matrix *"maps requirements to code symbols and
test class names rather than to AC-/TS- identifiers"*, so coverage rules 3 and 4 are declared **not
applicable** to it, while orphan and contiguity rules still apply.

**That is a legitimate matrix that a widened parser must not start failing.** It is evidence that
"unparseable" and "wrong" are different things, and the declared-gap mechanism already exists to say
so. **Establish for each of the eight whether it is a legacy shape to be parsed or a deliberate
different mapping to be declared.** They will not all be the same answer.

## What to measure, and report before changing anything

1. **For each of the eight**: legacy-shape-to-parse, or deliberate-mapping-to-declare? Cite the
   matrix, not an inference from the column count.
2. **A dry run**: if the parser accepted the legacy shapes, what would coverage rules 3 and 4 then
   say — **per package, including all six that parse today.** Not a total.
3. **Which currently-green packages would go red**, and whether each is a real gap newly revealed or
   a rule newly misapplied. **Those are opposite outcomes and must not be reported as one number.**

## Then, and only after a ruling on the measurement

Widen the parser to the shapes established as legacy, and declare the rest. **Per `DEC-L-061`, the
convention is declared in data and reported every run** — a matrix shape that matches nothing
declared **fails**; it is never inferred and never a fallback.

## Done when

- The measurement above is reported and ruled on **before** the parser changes.
- **Per-package before/after, including the packages already green.** From the coder's own T-060
  regressions: FP-009 got *worse* while the total improved by fifty-five, and FP-010 went green-to-red
  inside a run that looked like a large win. **Neither was visible in a total, and both were caught by
  the table.**
- Every failure mode planted and demonstrated — `DEC-L-059`.
- No document reformatted to satisfy the parser without the ruling saying so explicitly.
- Non-gated: no `src/`, no `tests/`. Push and wait for `MERGE T-061`.
