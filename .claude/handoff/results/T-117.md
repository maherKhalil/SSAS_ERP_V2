# THE MECHANISM, AND IT FAILS IN BOTH DIRECTIONS

## Under-reports: the closure cannot see a static class

```csharp
current.GetConstructors(BindingFlags.Public | BindingFlags.Instance)
  .SelectMany(constructor => constructor.GetParameters())
```

**The walk is constructor parameters, resolved to class implementations.** A `static` class has no
constructors and is never a parameter, **so it can never enter a closure.**

**`PayrollCalculator` is static.** It is where every payroll refusal is returned — and **it has never been in
any site's closure, in any run of this register.**

## Over-reports: a comment counts as a code path

```csharp
return ErrorFieldsBySymbol()
  .Where(entry => source.Contains(entry.Key, StringComparison.Ordinal))
```

**A raw substring match over the whole file.** A symbol named in a comment is indistinguishable from one
returned by code.

**`DEC-L-074` inside the register** — a name mentioned is not a claim — in the instrument built to find
exactly that class of mistake.

## And that is precisely what happened in T-115

I wrote, in `CalculatePayrollRunCommandHandler`'s source:

**A comment. In a seed's file.** The site became "responsible" for the code, the code was genuinely

**It found a true defect for a false reason.** Had I phrased that sentence differently, the 500 would still
