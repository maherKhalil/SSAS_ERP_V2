# T-032 — The module enablement seam, and the guard that keeps it complete

- **Branch:** `agent/T-032-enablement-seam` — branch from `main`
- **Module:** Platform + BuildingBlocks + Host
- **Issued:** 2026-08-26
- **Depends on:** T-031 merge. **First gated task since T-018.**

## Goal

The owner has chosen the enablement gate. `BR-PLT-0008` is the only *shall* about behaviour in the
entire authority, and today all seventeen route groups mount unconditionally — every tenant reaches
every module regardless of plan.

**This task installs the seam and the guard. It does not satisfy `BR-PLT-0008`, and it must say so.**
There is no subscription data yet: `OD-SUB-0004` puts the assignment in the Platform database and the
build obligation is *no backfill and no default plan*, so real entitlement arrives with the commercial
plane's schema in the next task. What ships here is the mechanism every module must pass through, and
**an architecture guard that makes a new module unable to skip it** — which is the whole reason
`OD-SUB-0003` ruled the gate goes before the next module.

A seam without data is worth shipping. A module added after it cannot be ungated by omission.

## Acceptance criteria

- [ ] **Each gateable module declares a stable module key**, on `OD-SUB-0005`'s unit: the thing that
      already carries exactly one `IPermissionCatalogContributor` and one `Add*Module()` — HR,
      Finance/GL, Payroll, Attendance. **Four keys, not seventeen** — HR alone mounts seven route groups.
- [ ] **One gate mechanism applies to every gateable route group**, a sibling of
      `PermissionEndpointConventions` rather than new authorization architecture (`DEC-SUB-0006`). A
      request to a route of a module the tenant does not have returns **403 Forbidden** (`OD-SUB-0006`),
      refused before the handler runs.
- [ ] **Platform-plane routes are not gated** (`REQ-SUB-0013`) — Host, authentication, support
      authentication, localization, identity/access, support authority, company. Seven groups exempt,
      ten gated. A disabled tenant must still be able to authenticate.
- [ ] **An architecture guard asserts the seam is complete**, and it must fail on the code as it stood
      before this task (`DEC-L-016`): every module-owned route group passes through the gate, and no
      platform-plane group does. **Demonstrate it** — add an ungated module route, watch it fail,
      remove it, report both.
- [ ] **Entitlement resolves through one contract with exactly one implementation, explicitly
      transitional**, which grants every module to every tenant and is named so a reader cannot mistake
      it for the real one. A test asserts it is the only implementation, so the next task replaces it
      rather than adding beside it. **Entitlement never travels in the token** (`DEC-SUB-0005`).
- [ ] Gate green under `DEC-L-008`, **`Integration.Tests` runs**, and merged on green per `DEC-L-007`.

## Design constraints

- **The two planes stay mechanically separate.** `RequirePermission` and `RequirePlatformPermission`
  are two methods precisely so a caller cannot choose the wrong plane by passing a flag; the module
  gate follows that shape rather than adding a parameter to an existing one.
- **The transitional resolver must be impossible to mistake for finished.** Name it for what it is, and
  say in the file what replaces it and when.
- **Do not gate on the route prefix.** The unit is the module key. HR's seven groups share one key, and
  a prefix-based gate would need a second, divergent notion of module — the thing `OD-SUB-0005` ruled
  against.
- Zero warnings. The baseline to move is Architecture 466, Platform 977, HR 326, API 685,
  Payroll 56, Attendance 59, Finance 46, Integration 782 both configurations.

## Tests required

- `Architecture.Tests` — the completeness guard, demonstrated failing.
- `Platform.Tests` — the resolver contract and the transitional implementation's behaviour.
- `API.Tests` — a gated route refused with 403 for a tenant without the module, and a platform-plane
  route reachable regardless. **Under the transitional resolver the first is hard to exercise honestly
  — if it cannot be tested without the data, say so rather than writing a test that asserts nothing.**
