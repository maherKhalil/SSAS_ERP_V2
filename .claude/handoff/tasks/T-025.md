# T-025 — Make the two registers checkable: `depends_on` for ADRs and decisions

**Runs while the architect writes FP-015. Touches no `src/`, no `tests/`.**

## The problem, and it is now two registers rather than one

`ADR-001..016` and `023..030` have no machine-readable dependency edges. `trace-check.py` covers
packages (checks 1–6), master registers (check 7) and decision-register agreement (check 8) — **it
does not check that an ADR's dependencies exist, are Accepted, or are not superseded.**

**And `DEC-L-057` found the decision register has the identical defect**, discovered the expensive
way: `DEC-L-054` prescribed `git rev-parse <ref>:<path>` in the morning and `DEC-L-056` restricted
the variable that form silently requires at midday. **They conflicted for three hours while both
windows had read both rules.** Nothing connected them because nothing could.

## Part A — ADR dependency edges

Add `depends_on:` to the front matter of `ADR-001..016` and `ADR-023..030`. **Derive each edge from
the ADR's own text, not from a guess about what it probably relies on** — cite the sentence in the
result where the edge is not obvious.

**`ADR-028` is a reservation, not a gap.** `OD-DOC-009` records *"ADR-028 IS V5'S TO WRITE"*. An
absent target that is a deliberate reservation must be representable, or the checker will report a
false positive forever — and this exact ADR was carried on the board as a false High finding for
nine tasks before anyone checked it. **Decide how a reservation is expressed and say so in the
result.**

## Part B — decision-register edges, which is the new half

`DEC-L` entries have no way to say *this rule prescribes a mechanism* or *this rule restricts one*.
Add enough structure that `DEC-L-056` restricting `MSYS_NO_PATHCONV` can be mechanically related to
`DEC-L-054` requiring it.

**Do not over-model this.** The question the register must answer is narrow: *when I restrict X, what
already depends on X?* A full ontology is not wanted and will not be maintained. **If the honest
answer is a `mechanism:` and `restricts:` pair of free-text keys plus a grep, that is a better
outcome than a schema nobody fills in.**

## Part C — extend `trace-check.py`

A check that fails when: a `depends_on` target does not exist; a target is `Superseded`; or a
decision restricts a mechanism another live decision prescribes.

**Reservations must not fire.** And per `DEC-L-059`, **demonstrate each failure mode by planting
one** — a dangling edge, a superseded target, a restrict/prescribe collision — rather than reporting
that the code looks right. Three checks built yesterday were wrong on first run and none was caught
by reading.

## Done when

- Every `ADR-001..016`, `023..030` carries `depends_on` (possibly empty, explicitly).
- `trace-check.py` fails on each of the three conditions, **each demonstrated by a planted case.**
- It passes clean on the register as it stands, or names exactly what is wrong — **and if it finds a
  real dangling edge, that is a finding to report, not a thing to quietly fix.**
- `GATE_SCOPE=TASK`. No `src/`, no `tests/`, so this is a **non-gated** task: push and wait for
  `MERGE T-025`.

**Check back before Part B's shape.** A register format is a decision, and the cheapest correct
answer is likelier than the complete one.
