## Part A — neither deleted nor lost. Never allocated.

**The task offered two categories and the answer is a third.**

**Nothing was deleted.** `git log -S` over fourteen sampled identifiers across all six packages:

```
TS-IAM-0016  TS-IAM-0025  TS-IAM-0037    0 commits added or removed it
TS-AUTH-0026 TS-AUTH-0043 TS-AUTH-0057   0 commits
TS-TEN-0009  TS-TEN-0039                 0 commits
TS-CMP-0010  TS-CMP-0029                 0 commits
TS-EMP-0013  TS-EMP-0032                 0 commits
TS-POS-0068  TS-POS-0069                 0 commits
```

**They never existed.** No commit ever added one and no commit ever removed one.

**And they were never meant to.** The legacy packages allocate scenario numbers in **themed blocks
starting at round boundaries**:

```
FP-001   Domain and application 0001-0015 | Tenant selection 0020-0024 | API 0030-0036 | Persistence 0040-0048
FP-002   Core 0001-0019 | Tenant selection 0020-0025 | Session 0030-0042 | API 0050-0056 | SQL 0060-0068
FP-005   Domain 0001-0009 | Application 0020-0028 | SQL 0040-0048 | API 0060-0068 | Architecture 0080-0089
```

**The "missing" identifiers are the unused tails of those blocks** — 0016-0019 sits between the Domain
block and Tenant selection, 0025-0029 between Tenant selection and API, and so on.

**115 of 115 gaps across the six packages end at a round-number boundary. Every modern package has
zero gaps.**

That is not a coincidence and it is not a defect: **block allocation is the legacy convention, sequential
is the modern one, and the contiguity rule asserts the modern one against both.** Same shape as
`BRULE-` contiguity, and as co-owned contiguity — a rule whose domain was never established.

**Per identifier, as asked: all of them, in all six packages, are unallocated block tails.** There is
no mixed case. **The tidy answer was the true one this time**, which is worth saying plainly because
the instruction to distrust it was right and the distrust cost one `git log`.

## Part B — wired, and red only on a rise

```
holding at baseline                   exit 0
FP-003 baseline lowered 12 -> 5       !!! REGRESSION: 12 > 5      exit 6
                                      "baseline NOT updated"
baseline raised   1 -> 9              improved: lowers to 1, never rises again
```

**`--baseline` returns 6 on a rise and 0 otherwise, deliberately overriding the standing-count code.**
Without that the gate would have gone red on all seventeen — the hard zero the ruling rejects, and the
shape that gets a gate switched off.

**The instrument writes the baseline**, ratcheting down only: a package that improves lowers its own
bar and cannot raise it again.

## PARTIAL — the end-to-end gate run did not happen, and why

```

largest consumers: Memory Compression 885 MB, msedgewebview2 848, brave 590/417/364, MsMpEng 381
```

because a run died under it, and lowering a precondition to obtain a pass is the one thing the charter
forbids outright. **A green bought that way would have been the most expensive line in this result.**
