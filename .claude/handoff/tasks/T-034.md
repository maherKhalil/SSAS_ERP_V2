## Goal

You found this in T-032 and it cost 171 red tests to surface. `EmployeeApiTestHost`,
`DepartmentApiTestHost`, `PositionApiTestHost`, `GlApiTestHost` and `PayrollApiTestHost` each build
their own `WebApplication` and map module endpoints by hand. **Any future required service on a module
route group breaks all five identically, and nothing points at them from the module side.**

Your own comparison is the spec: same shape as `IPermissionCatalogContributor` registration — explicit,
never discovered — **except the permission catalog fails at startup while this failed per request.**
A startup failure is caught by the first test; a per-request failure surfaced as 171 failures that
looked like a product bug.

The cutover is coming and will change what a module route needs. Close this before it does.

## Acceptance criteria

- [ ] **A module route group's service requirements are declared once and satisfied once**, so a host
      that mounts module endpoints cannot omit a required registration by silence. Whether that is a
      shared composition helper, an extension the hosts call, or a guard that fails at startup is
      yours — **choose and say why in the result.**
- [ ] **A test that fails if a sixth host is added without it**, or if one of the five stops using it.
      `DEC-L-016`: demonstrate it failing on the code as it stood before this task.
- [ ] **The failure mode moves from per-request to startup**, or the result explains why it cannot.
      That is the substance of the finding, not the five registrations themselves.
- [ ] **No test's assertions change.** These hosts exist to exercise module endpoints; this task changes
      how they are composed, not what they prove. Counts move only if you add tests for the mechanism.
- [ ] Gate green under `DEC-L-008`, **Integration runs**, merged on green. Baseline: Architecture 474,
      Platform 1015, API 692, HR 326, Finance 46, Payroll 56, Attendance 59, **Integration 791 both**.

## Design constraints

- **Do not solve it by making the gate lenient.** You refused that in T-032 and the reasoning holds:
  a host mounting a gated surface that cannot resolve entitlement is misconfigured.
- **Prefer a mechanism that fails loudly at startup over one that documents an obligation.** The
  permission catalog is the precedent worth beating, not matching — it is explicit and never
  discovered, and that is why this was possible.
- If a shared helper would couple the test hosts to production composition in a way that hides a real
  difference between them, **say so** — five hosts that differ deliberately are not the same problem
  as five that differ by accident, and I do not know which these are.
