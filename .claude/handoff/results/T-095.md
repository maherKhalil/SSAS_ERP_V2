# FOUR THINGS THE COPYING TURNED UP, AND THREE WOULD HAVE BEEN WRONG TO PROPAGATE

## 1. Six of the twenty-seven were a MIS-DECLARATION, not debt

T-094 recorded six `Employee.*` codes at `EmployeeImportExportTransportContracts` as *"scope refusals the
import surface inherits"*. **Reading the route before copying is what caught it.**

`EmployeeEndpointRouteBuilderExtensions` answers the import and export ROUTES through
`EmployeeApiErrorMapper.Map(...)`. **`EmployeeImportRowErrorMapper` renders PER-ROW errors inside the
report body and never sees a route-level refusal.** All six are already mapped, at the site that answers.

**Adding six arms to a row mapper that cannot receive them would have been the mechanical answer and the
wrong one: dead arms that read as coverage.**

**A fifth floor, recorded with the other four: ONE ROUTE CAN HAVE TWO MAPPERS** — one for the envelope, one
for the items inside it — **and the site-to-mapper edge cannot express that.** Both sites seed from the same
handlers, so this site's derived set is a superset by construction.

## 2. The guard went red before green and found TWO PRE-EXISTING disagreements

```
Company.ContextRequired          403 at four sites, 400 at Payroll
EmployeeImportRun.InvalidActor   403 at the employee mapper, 500 at the import contracts
```

Neither was introduced by T-094 or T-095. The second is the exact defect `EmployeeApiErrorMapper`'s own
header warns about — *"tells the caller to retry something that will never succeed, and pages an operator
for a working system."*

**Recorded as an exact set, not resolved.** Copying one site's answer over the other would be choosing a
status, and the wrong choice propagates a defect rather than leaving one. Resolving either must edit the
list; a third cannot arrive quietly.

## 3. Two more it reported were the guard's own fault

A bare `PositionNotFound` resolved by member name across every transport type found the wrong constant:
**`EmployeeImportExportTransportContracts` declares it 400 and `PositionApiErrorMapper` declares it 404, and
both carry the string `position.not_found`.** The guard reported two disagreements that do not exist.

**`DEC-L-069`'s symbol-versus-code collision, inside the guard rather than in a ruling.** Bare names now
resolve from the site's own source; only a qualified name goes to reflection.

**And that collision is itself a real finding I am not ruling:** one wire code, `position.not_found`,
carries 400 on one surface and 404 on another. The guard cannot see it, because it compares arms rather
than strings.

## 4. `Gl.AccountNotFound` keeps GL's code string, not only GL's status

`DEC-L-079` fixes the status at 404. The string stays `gl.not_found` rather than becoming
`payroll.not_found`, because **what was not found is the ledger account** — naming the wrong missing thing
would be a worse answer than the 500 it replaces. The literal is repeated rather than referenced;
`SSAS.Payroll.API` does not reference `SSAS.GL.API` and must not.

## The six at `PlatformAuthentication` — reported, and my earlier framing was wrong

**Declarations, all in `AuthenticationErrors.cs`:**

```
GenericCredentialFailure           "Authentication.Failed"
GenericTenantSelectionFailure      "Authentication.TenantSelectionFailed"
AccessTokenIssuanceUnavailable     "Authentication.AccessTokenUnavailable"     9 raise sites
InvalidAuthenticationSession       "AuthenticationSession.Invalid"             6 raise sites
GenericRefreshFailure              "AuthenticationSession.RefreshFailed"       4 raise sites
IdentityAccessErrors.ConcurrencyConflict  "Persistence.ConcurrencyConflict"    PlatformUnitOfWork.cs:25
```

**The auth routes use NO mapper.** They branch inline on the exact `Error` instance:

```
GenericTenantSelectionFailure -> 401 authentication.selection_failed ; anything else -> 503 service.unavailable
GenericRefreshFailure         -> the cookie-clearing 401 path        ; anything else -> 503
InvalidAuthenticationSession  -> 204 (logout is idempotent)          ; anything else -> 503
```

**So the collapse is not "everything answers one generic 401".** It is: *the expected error answers 401 or
204, and everything else answers 503 service.unavailable.*

**That sharpens my flag and corrects it.** I said `Persistence.ConcurrencyConflict` would answer as a
generic authentication failure. **It answers `503 service.unavailable`** — which is wrong in a different
and arguably worse way: it points a caller at an outage when the fix is to retry a concurrent write.
`Authentication.AccessTokenUnavailable` also lands in the 503 bucket, and there it is arguably right.
