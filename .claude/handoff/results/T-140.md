# WHAT WAS STALE, AND WHY IT WAS NEVER A DEFECT

**Two entities were added and the hardcoded expectations that guard them were never updated:**

```
OneOffPayment     T-110    -> PayrollOneOffPayments, the 8th Payroll% table
UserEmployeeLink  T-082    -> the platform schema's identity-to-employee mapping
```

**The product is right and the tests were behind**, checked end to end rather than assumed:
`TenantCutoverCopyService` takes an `ITenantModelSource`; `ComposedTenantModelSource` is built from
`IEnumerable<ITenantModelContributor>` — **the same collection the runtime context resolves.** The manifest
is model-derived and self-updating; only the tests hardcode.

**They must hardcode. A test that also derived would be tautological.** The hardcoding IS the guard, so it
drifts by construction whenever an entity is added.


**A count fix that leaves the test named `..._all_seven_payroll_tables` is half a fix**, so the name moved
with the number.

# ⚠ THE EIGHTH FAILURE WAS HIDING A NINTH, AND THE MECHANISM IS THE DAY'S SHAPE AGAIN

**Verification came back 35/36.** `A_retry_revalidates_completed_tables_and_never_duplicates_them` still
failed — now with **`Expected: 33, Actual: 34`**, a number I had never seen.

```csharp
Assert.Equal(35, first.Value.TablesCopied);    // I fixed this one, 34 -> 35
Assert.Equal(33, second.Value.TablesCopied);   // ...which revealed THIS one
Assert.Equal(1, second.Value.TablesAlreadyComplete);
```

**34 = 35 total less the one already complete.** Equally stale, equally caused by `OneOffPayment`.

**I built the fix list from the suite's failure messages** — and **a test stops at its first failing
assertion**, so those eight were **first failures rather than all stale expectations.** The second
assertion could not fail while the first already had.

**Same property as the rest of the day: a summary read as data.** A failure list summarises *where each test
stopped*, not *what is wrong with it* — and the remedy was the same as every other instance: **open the
thing the summary summarises.** After fixing, that test passes and the sweep for remaining two-digit counts
in all three files comes back with only corrected values.
