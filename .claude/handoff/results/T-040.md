## Criterion 4 — the cache holds the facts, not the answer

**Both options in the spec were compromises, and the second could not have been built as written.**
Keying an entry so it cannot outlive `TermEndUtc` requires **knowing `TermEndUtc` to construct the key**,
which requires the read the cache exists to avoid; any approximation of it is a TTL under another name,
and `OD-SUB-0004` ruled a TTL out explicitly.

**A derived answer can go stale with nothing written. The facts it derives from cannot** — a subscription
record, a plan's modules and a tenant's grants change only when something is written, which is exactly
the event invalidation-on-change already covers. So expiry needs no invalidation event **because it was
never a cached value**: it is evaluated on read against the clock.

**Proved at two levels, and the second is the one that rules out the alternative explanation.**

- `Platform.Tests` — one snapshot, built once and never rebuilt, answers `true` at day 29 and `false` one
  tick past the term. Only the clock moved.
- `API.Tests` — a request before expiry caches; the clock advances past `TermEndUtc`; the next request
  gets **403**. **The stub reader's counter is still 1.** Nothing was written, nothing was evicted, and
  no re-read happened — so the refusal can only have come from evaluating the cached term.

## Criterion 3 — no special case, and the test asserts why

An expired tenant is refused a gated route with **403** and reaches a platform-plane route normally.

**The platform-plane assertion is that the reader's read count is `0`** — not that the route returned
200. The outcome does not depend on what entitlement would have answered, which is the difference
between *happening to be right* and *structurally right*.

**It needs no special case because `RequireModule` is applied to module route groups and nothing else,
and the platform plane carries no module key** (`REQ-SUB-0013`). That is a fact about the exemption doing
its job rather than about care in this code — had the platform plane been gated, an expired tenant would
have been locked out of the surface it renews from, and nothing in this file could have fixed it.

## Criterion 5 — the fan-out, with its negative case

The cache keeps a **plan → tenants index**, so `InvalidatePlan` evicts every tenant on a shared plan.
Tested with three tenants on one plan and a fourth on another.

**And the negative case, which is the one that catches a stale index:** a tenant that changed plans is
**not** evicted by its old one. An index that lies is worse than no index, because the next person
reasons from it.

## Placement, and the layering it protects

The **read** is `Platform.Infrastructure`; the **adapter** is `Platform.API`, the one project referencing
both the transport contract and Platform's application layer. `Infrastructure` taking a dependency on
`BuildingBlocks.Api` would be the inversion the dependency guards exist to catch.

The **cache is a singleton** because it outlives a request by design; the **resolver is scoped** because
it reads the request's tenant.

## Stated limits

- **The cache is process-local.** Two hosts hold two caches and an invalidation on one does not reach the
  other. Harmless today — nothing writes a subscription, so nothing can invalidate — but `ADR-018` names
  the multi-instance case and a distributed invalidation is owed before this runs behind more than one
  instance. Recorded in the file, queued as T-042.
- **A tenant with no subscription now reaches no gated module.** Correct under `CON-0001` and the ruled
  interim state, asserted as such in a test rather than left implicit. T-041's trial is what makes it
  safe.
