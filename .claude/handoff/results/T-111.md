# KIND 4 — THE PREMISE DOES NOT HOLD, AND 46 "DEFECTS" DISSOLVE

`CreateEmployeeRequest` declares **every** member nullable — `fullName`, `employmentDate`, all of them —
and its own comment at `:30` says `positionId` is *"REQUIRED FROM DAY ONE... the column ships NOT NULL."*

**Nullability in these DTOs is a DESERIALIZATION convention, not an optionality signal**: a missing JSON
member must deserialize to null rather than throw. **`requiredFields` is what expresses requiredness, and
the two are orthogonal.** So "optional in C#, required in the schema" is the *correct* pattern.

**The real kind-4 defect — a member the API INTENDS to be optional but which `requiredFields` makes
mandatory — is not detectable from types at all.** It needs intent, and no walk has it.
