# T-022 — FP-014's master-register acts: the identifier space and the rules

- **Branch:** `agent/T-022-fp-014-registers` — branch from `main`
- **Module:** Platform (commercial plane) / governing documents
- **Issued:** 2026-08-25
- **Depends on:** T-026 merge — FP-014's citations had to be sound before its rules entered a governing document

## Goal

FP-014 is ratified and its citations are now clean. Two obligations remain, and both change **governing
documents** rather than a package.

`OD-SUB-0002` ruled a new `REQ-SUB` prefix, **added at ratification**, following FP-013's `REQ-ATT`
precedent. And `DEC-L-012` ruled that promotion of a package's `BR-` rules to the master register is a
**ratification obligation, not an open question** — with `trace-check` check 7 as the mechanism and a
new `UNPROMOTED` row after a package merges counted as a ratification defect.

`BR-PAY` and `BR-ATT` were both lost at exactly this step. This is the first package to close it.

**The roadmap entry and the README front-matter are T-027**, deliberately separate: those state what
the product *is*, and these state what its identifiers *are*.

## Acceptance criteria

- [ ] **`Requirement-Numbering.md` gains `REQ-SUB-0001` and `BR-SUB-0001`** in the same shape as the
      existing prefixes. `SUB` currently appears **zero** times in that file — verify before and after.
- [ ] **`BR-SUB-0001` … `BR-SUB-0021` are promoted into the master `Business-Rules.md`**, in that
      file's own section shape (`## BR-SUB-####` / `### Title` / statement), carrying the rule as
      FP-014 states it. **Do not re-word a ruled rule while moving it** — a rule that changes meaning
      in transit is worse than one that never moved.
- [ ] **`trace-check` no longer reports `BR-SUB` under `UNPROMOTED`.** It should still report `BR-PAY`
      and `BR-ATT`, which are `DEC-L-012`'s existing backlog and explicitly not this task. Paste the
      check-7 section showing two rows where there were three.
- [ ] **FP-014 stays GREEN, `0 unruled`**, and the package-level results for the other thirteen are
      unchanged. A master-register act must not perturb a package.
- [ ] `git diff main...agent/T-022-fp-014-registers --stat` shows **exactly two files**, both under
      `docs/00-Master-Product-Specification/`.

## Design constraints

- **`Business-Rules.md` still lists Payroll and Attendance under "will be added in future releases".**
  Subscription must not join that list — it is being added, not deferred. If that section needs a line
  changed to stay true, change it and say so; if not, leave it.
- **Match the master file's own section shape exactly.** It is a governing document read by people who
  will not have read FP-014.
- **Numbering is contiguous from 0001** and `trace-check` will say so if it is not.
- If a `BR-SUB` rule reads oddly outside FP-014's context — because it leans on a `DEC-SUB` or an
  `OD-SUB` the master file has never heard of — **say so rather than paraphrasing it into
  self-sufficiency.** That is a real finding about the rule, not a formatting problem.
