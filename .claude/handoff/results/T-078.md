## 1. Which modules have this shape — all of them, and the consequence differs

**Ten mappers exist and every one has a fallthrough. They are not the same fallthrough:**

```
AttendanceApiErrorMapper.cs                 _ => ApiErrors.WriteFailure          500
GlApiErrorMapper.cs                         _ => ApiErrors.WriteFailure          500
DepartmentApiErrorMapper.cs                 _ => ApiErrors.WriteFailure          500
EmployeeApiErrorMapper.cs                   _ => ApiErrors.WriteFailure          500
PositionApiErrorMapper.cs                   _ => ApiErrors.WriteFailure          500
PayrollApiErrorMapper.cs                    _ => ApiErrors.WriteFailure          500
CompanyApiErrorMapper.cs                    _ => ProblemResults.WriteFailure
PlatformSupportAuthorityApiErrorMapper.cs   _ => ProblemResults.WriteFailure
IdentityAccessApiErrorMapper.cs             _ => ProblemResults.RequestInvalid   400  <-- different
LocalizationApiErrorMapper.cs               _ => null!                                <-- different again
```

**Two Platform mappers do NOT fall through to a server error.** `IdentityAccessApiErrorMapper` answers
**400** for an unmapped code — an unknown business refusal becomes "your request was invalid", which is a
wrong answer rather than a server-fault answer. `LocalizationApiErrorMapper` returns `null!`. **I did not
chase either; they are Platform-plane and outside this task's four modules.** Reported because the
premise "the fallthrough is a 500" is true of the six module mappers and **not universally true**.

## 2. How errors are enumerable — and what bounds this

**Declared errors are `public static readonly Error` fields on `static class *Errors`**
(`WorkingCalendarErrors.cs:9,13,17,...`), and `Error` is `record Error(string Code, string Message)`.
**Reflectable, exactly as permission constants are.**

**But 21 errors are constructed inline**, and where they are is the finding:

```
in a business module   1    AttendanceEndpointRouteBuilderExtensions.cs:568   new Error("Attendance.RequestInvalid", ...)
in Platform           20    Company / Identity / Localization / Roles / TenantUser / Tenant handlers,
                            plus two Infrastructure exception types
```

**An inline error cannot be enumerated and therefore cannot be guarded.** For the four modules this
costs one error. **For Platform it would cost twenty**, which is most of why this guard covers the
modules and not the platform plane. That bound is a property of the code, not a choice of scope.

# THE GUARD

`tests/Architecture.Tests/ModuleErrorMappingArchitectureTests.cs` — four theory cases plus one fact.

**Reflection for the errors, source text for the mapping, and the split is forced rather than chosen.**
`WriteFailure` is a **deliberate** target in HR — three arms in `EmployeeApiErrorMapper`, one in
`DepartmentApiErrorMapper` — so calling `Map(error)` cannot distinguish *mapped to WriteFailure* from
*fell through*: both return the same singleton. **The presence of a `"<code>" =>` arm is the only fact
that separates them, and it exists only in the text.**

The error side is reflection over real `Error` fields rather than a regex over string literals, because a
literal in a comment is not a code. **That is also an independent confirmation of the shell measurement
above — a different method reproduced the same five**, and had it not, the exact-set assertion would
have failed rather than passed quietly.

**The fallthrough is kept.** A default is defensible; what was missing is a guard that nothing relies on
it. Nothing was removed and nothing was made to throw.

**Per-module, never aggregated.** `Assert.True(declared.Length > 0, ...)` per module — an aggregate is
satisfied by the largest module while the smallest goes unexamined, which is T-073's one-policy-wide
plane exactly. `ModuleNames` is a named theory source so a module dropping out of the surface list
fails rather than silently reducing the theory to three cases.

**The register is an exact set, not a ceiling.** Mapping one of the five must also fail. A "no more than
N" rule passes when one is mapped and another added — the swap argument from T-077, one file over — and
the register records debt, so paying it down is something someone should have to write down.

## For the architect

- **Blocked / needs a decision:** **five status codes.** Two Payroll overtime-tier errors and three
  `Employee.Position*` errors currently answer 500. **Not mine to choose** — each needs a status and a
  code, and the mapper arm follows from that.
- **The premise needed narrowing:** *"the fallthrough is a 500"* holds for the six module mappers. Two
  Platform mappers do something else — `IdentityAccess` answers **400**, `Localization` returns `null!`
  — and an unmapped identity error answering *"your request was invalid"* is a different wrong answer
  from a server fault. **Outside this task's scope; named because the premise was stated generally.**
- **Twenty inline errors in Platform are why this stops at the module boundary.** Not a scoping
  preference — an inline error has no field to enumerate, so no reflection-based guard can reach it.
  Extending this to Platform is a different task and probably starts by moving those twenty.
