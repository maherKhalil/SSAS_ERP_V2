# THE RULING ARRIVES

```
consumed = there exists an APPROVED, UNREVERSED run holding this one-off
```

**T-110 ruled it and could not implement it.** A reversal wrote nothing on the run, so *"unreversed"* was
not a question Payroll's own data could answer — **the instruction was recorded consumed unconditionally,
stranding an unpaid obligation the moment its run was reversed.** T-112 added `ReversedUtc`; this is the
ruling becoming expressible rather than a new decision.

---

# IT IS A JOIN, NOT A RESET, AND THAT IS THE WHOLE DESIGN

```csharp
payment.ConsumedByPayrollRunId == null || reversedRuns.Contains(payment.ConsumedByPayrollRunId)
```

**The alternative was clearing the reference when a run is reversed.** That destroys the record of which run
paid it — **the reason T-110 chose a reference over a boolean was that "every payroll question about a
payment is which run"** — and it is a second write that can fail after the reversal has already posted to
the ledger.

**Derived, so there is no state to get out of step.** A reversed run stops satisfying the predicate on its
own, exactly as the ruling described.

---

# ⚠ AND THE AGGREGATE'S REFUSAL HAD TO NARROW, WHICH IS THE PART WORTH ARGUING

**`MarkConsumedBy` refused ANY second consumption. Under the ruled predicate that blocks the correction
itself.**

**Narrowed to: the same run cannot consume it twice.** A different run taking it over is the correction, and
refusing that is the stranding the ruling rejected.

## So where does the double-payment invariant live now?

**Not in the aggregate, and deliberately. It is structural, in two places that cannot drift:**

```
GetUnconsumedForPeriodAsync   offers an instruction only while unconsumed, or its run is reversed
the filtered unique index     permits ONE UNREVERSED run per period
```

**Two LIVE runs can never both reach the same instruction.** An aggregate check would be a third statement
of a rule those two already enforce — and the failure it guarded against is now impossible **at the
database** rather than refused in memory.

**What it still refuses is one run repeating itself**, which is a defect in the approval path rather than a
correction.
