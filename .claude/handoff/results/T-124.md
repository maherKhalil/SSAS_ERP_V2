**I justified moving the invariant out of the aggregate with `DEC-L-080` — a third statement of a rule two
places already enforce. That is an argument a later reader can simply disagree with**, and defence in depth
is legitimate where a failure is expensive.

**The decisive reason is that the aggregate CANNOT evaluate the predicate.** *Consumed* is *an approved,
UNREVERSED run holds this*, **and `OneOffPayment` holds a run identifier, not a run.** An aggregate check
could only refuse any second consumption — blocking the correction — or be handed the verdict by its caller,
**which is not an invariant, it is a parameter.**

**Replaced in the aggregate's own comment.** It cannot be argued with; the version I wrote could.

## Why this one CAN live in the aggregate, and it is the distinction that matters

**Data versus conclusion.**

- *"Is this run reversed"* is **the answer to the predicate**. An aggregate accepting it asserts nothing of
  its own.
- *"Which period is this run for"* is **a fact about the run**, which the aggregate then **compares against
  state it already holds.** It had one half of the comparison and was simply not given the other.

**`MarkConsumedBy(runId, runPeriodId)`, refusing `ConsumingRunIsForAnotherPeriod`.** Planted: removing the
comparison fails the test.
