## 1. `AC-SUB-0047` — the ordering clause amended, the condition kept

It read *"the enablement gate is not active in the release that introduces the migration."* **The gate is
active in the release that introduces the seed migration**, so the clause was false — and false in the
authority a deployer reads, which is what separated it from the day's other doc defects. Every other one
misled a reader about history; this one would have misled someone about what to do next.

Amended in all three places — `acceptance-criteria.md`, `test-scenarios.md`, `traceability-matrix.md` —
to: **no release leaves a tenant reachable by a gated route with no subscription record; the gate and the
trial seed ship in the same release, and the seed must not precede the gate within it.**

**Stated to fail in either direction.** T-040 without T-041 locks every tenant out of every module; T-041
without T-040 writes commercial records nothing reads. The board's constraint had only the first half, and
**a one-way constraint invites someone to satisfy it by reversing the order.**

### The declared gap stays, and that was the decision worth getting right

Closing it was available and would have looked defensible: T-041 added real tests that touch this area.
**They assert the OUTCOME — after the migrations run, no tenant is without a record — and `AC-SUB-0047`
states a CONDITION about a deployment.** No suite inside one build can see what shipped beside it.

So the gap is **narrower and not closed**, and each of the three sites says which half is covered.
**Closing it would have bought a cleaner count for a false claim.**
