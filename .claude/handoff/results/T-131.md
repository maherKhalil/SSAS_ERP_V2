# THE FIX

**`OvertimeTierKey` in `SSAS.BuildingBlocks.SharedKernel`** — the one place the vocabulary is defined.
**Both domains already reference SharedKernel and neither may reference the other** (`ADR-012`), so it is
the only home that needed no new dependency.

**The rule is the product's existing one, not a new invention.** `LeaveTypeCode`, `WorkingCalendarName` and
the login-identity partition all normalise operator-entered labels as **trim then `ToUpperInvariant`**. A
tier is the same kind of label, so it follows the convention rather than growing a fourth one.

**`MaximumLength` moved too.** It was declared on both sides **with a comment on each saying the two must
agree** — `DEC-L-080` written down twice and then obeyed manually. Both now cite the shared constant.

## Four points, and two of them are for data that already exists

```
AttendanceRecord factory       normalise on write     new records
PayElement.SetOvertimeTier     normalise on write     new elements
AttendanceSummaryService       normalise the GROUP KEY
PayrollCalculator lookup       normalise the element's tier
```

**The write points make new data correct. The read points are what make rows written BEFORE T-131 match,
without a data migration** — which is stated at both, because a reader would otherwise delete them as
redundant.

# WHAT THE FIX DOES NOT DO, STATED IN THE TYPE

**It equates case and surrounding whitespace. Nothing else.**

**`ar` is a configured culture and Arabic is caseless**, so `ToUpperInvariant` is a no-op for an Arabic tier
— **two Arabic labels differing by alef form (`أ` `إ` `ا`), tatweel, or harakat remain different keys.** So do
composed versus decomposed forms, and so does any typo that is not a case difference.

**That is a floor and it is deliberate.** Folding Arabic orthographic variants is a language decision with
real semantic risk — it is not obviously right that `إجازة` and `اجازة` are one tier — **and you scoped this
to the half nobody chose.**
